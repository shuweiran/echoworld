## 一、目标与背景

### 1.1 用户需求（原始表述）

剧本杀模式玩法升级：

1. LLM 先生成**概略剧本**（地图有什么地点 / 人物 / 线索 / 简单合理剧情线）；
2. 进入会话；
3. 后台异步生成**完整剧本 + 2D 地图**；
4. 一轮对话互相了解后进入 2D 地图态（**对话框收起**）；
5. 按地图规则探索（移动 / 调查 / 与角色对话），**加入某聊天时重新拉起对话框**；
6. 一般模式无地图正常显示（已实现）。

### 1.2 现状基础

| 基础 | 状态 | 证据 |
|---|---|---|
| 一般模式无地图版 + mode 自动分类（有主角→`protagonist` / 无主角→`director`） | ✅ 已完成（**P-0810-07**） | 本方案素材确认 |
| 剧本杀地图数据三层模型（契约 v1 → 生成器 → 对局注册表） | ✅ 已就绪 | 调研-剧本杀完整实现 §1.6 / §6.4 |
| 搜证 / 切图 / 足迹 / 线索 / 私聊 / 阶段机 / DM | ✅ 已就绪 | 同上 §4 / §6 |
| Gal 视觉小说界面（立绘 / 打字机 / SSE 直播 / 轮询增量） | ✅ 已就绪（P-0810-02/03/06） | docs/gal-界面设计.md |
| 「概略剧本先行」所需的异步化改造 | ❌ 未做（init 内同步双 LLM） | 调研-剧本杀完整实现 §2.1 |

### 1.3 目标形态

```
建局（概略剧本）→ 会话（一轮对话，对话框模式）→ 2D 地图态（对话框收起，按地图探索）
   ├─ 移动：节点式，客户端上报 + 服务端尽力校验
   ├─ 调查：search 扣 AP 得线索（复用现端点）
   ├─ 对话：discussion_say @角色 → 重新拉起对话框
   └─ 事件地点：触发旁白 → 拉起对话框
调查完毕 → 讨论 / 投票 / 揭晓（复用现有阶段机）
```

## 二、对局流程设计（阶段时序）

### 2.1 六步时序

| 步 | 动作 | 触发 | 数据 / 事件 | 对局阶段 |
|---|---|---|---|---|
| 1 | 玩家建局 → LLM 生成**概略剧本**（地点/人物/线索/剧情线，结构化 JSON）→ 前端展示概略 | `POST /api/script/init`（outline 模式） | 概略 JSON：`{locations[], roles[]（名字+一句话人设）, clues[]（标题+地点）, storyline, killer_hint?}` | **SETUP**（新占用：枚举已存在从未使用，L223） |
| 2 | 进入会话 → 后台异步生成**完整剧本 + 地图**，完成后 SSE 推送「剧本就绪」 | `POST /api/script/generate_full`（**新端点**，异步虚拟线程） | 完整 Schema v1 + MapContract v1（地图 LLM 8000 tokens / BSP 降级） | SETUP → INVESTIGATION |
| 3 | 一轮对话（互相了解，对话框模式） | 玩家发言 / AI 发言 | discussion_say / script_status 轮询（现链路） | INVESTIGATION（会话态） |
| 4 | 切换 2D 地图态（对话框收起）：**AI 合适时机提示 + 玩家可主动切换（双轨）** | AI 旁白提示（announcement 通道，broadcastSystemAnnouncement L2430-2450）/ 玩家点按钮 | script_phase / announcement | INVESTIGATION（地图态） |
| 5 | 地图探索：移动 / 调查（search 扣 AP 得线索）/ 与角色对话（discussion_say @角色 → 拉起对话框）/ 进事件地点触发旁白（拉起对话框） | 玩家操作 + AI 事件驱动 | 见 §3 | INVESTIGATION |
| 6 | 调查完成后进入讨论 / 投票 / 揭晓 | start_discussion / 讨论引擎自动 / start_voting / resolve | 复用现有阶段机（§3.1 状态机，D-012/D-013） | DISCUSSION → VOTE → REVEAL → ENDED |

### 2.2 关键设计要点

- **SETUP 中间态**：`ScriptGame.Phase.SETUP` 枚举已定义（ScriptGameService L223）但从未被任何 init 路径赋值（init 直接 INVESTIGATION/DISCUSSION，L621-625）——天然可作为「概略已生成、完整剧本待生成」的中间态挂载点，零破坏。
- **两阶段生成是本次改造核心**：现 `initGame` 在 init 请求内**同步双 LLM**（剧本 `callJson(prompt, 4000)` L557/L66；full 模式地图 8000 tokens/45s L632-638），概略先行即拆分此同步链路（详见 §4.1）。
- **「剧本就绪」通知承载方式**：可复用现有 `script_phase`（broadcastPhase L2414-2421）+ `script_status`（broadcastStatus L2452-2455）+ announcement 横幅；如需携带结构化 payload（完整剧本摘要 / 地图信息）则新增定向事件 `script_ready`（参照 `script_private` 推送模式，L1964-1967）——**设计决策**，见 §7。
- **一轮对话的定位**：发生在完整剧本就绪后、进入地图态前，处于 INVESTIGATION 阶段的会话态，作用是「互相了解」（角色介绍 / 背景交代）；AI 在合适时机（如各角色自我介绍完毕）发起进入地图的旁白提示，玩家亦可随时主动切换（双轨，不强制）。

## 四、后端改造点

### 4.1 两阶段生成（概略 → 完整）

**现状**：`POST /api/script/init`（ScriptController L79-127）→ `initGame`（L546-670）同步双 LLM——剧本 `generateScriptChecked`（L557，`callJson` 4000 tokens L66）→ full 模式同步 `generateMap`（L632-638）。

**改造**（对应调研 §2.3 六点插入方案）：

| # | 改造 | 位置 | 说明 |
|---|---|---|---|
| ① | 概略生成新方法 | `ScriptService` 新增 `generateOutline(theme, playerCount)` + `ScriptSchemaV1.buildOutlinePrompt` | 轻量 prompt，`callJson` maxTokens≈800-1200；输出 `{locations[], roles[]（名字+一句话人设）, clues[]（标题+地点）, storyline, killer_hint?}`；新代码零破坏 |
| ② | initGame 拆两阶段 | `initGame` **L555-570**（`generateScriptChecked` 调用点前）为插入点 | `outlineOnly=true` 时只生成概略 → `game.phase = Phase.SETUP`（枚举 L223 现成未用）→ toMap 附加 `outline` 键；`persistScript` / `saveSnapshot`（L627-629）概略态容错（scriptSchema 为空时分支） |

| ④ | 地图生成时机 | 从 init 内（L632-638）移至「完整剧本生成完成」后，**后台异步**（`discussionExecutor` 同款虚拟线程池，L214） | `generateMap` 本身无 phase 守卫（仅 session_id 存在性，L96-221），任何阶段可调；chat 版可配置地图已走此路径（D-034） |

### 5.4 mode 自动分类（已落地，P-0810-07）
