## 1. 测试目标

1. **全功能覆盖**：对已盘点的 55 项功能（核心对话引擎 27 + 2D 空间模拟 11 + 铁轨系统 10 + 前端 7）逐项给出可执行的测试方法，做到"有方法、可执行、有结论"。
2. **超长文本稳定性**（需求硬性要求）：至少 1 次专门用例，验证长上下文下不 OOM、不卡死、响应时间可接受、内容不丢失。本方案给出 3 个用例（第 7 章），其中 LONG-01 为必做项。
3. **回归安全**：以现有 84 tests 为基线，补齐 P0 缺口，保证每轮迭代 `mvn test` 全绿。
4. **缺陷显性化**：将已识别的已知缺陷（TrackScore 阈值 hardcode、剧本杀前端 P0 缺失、`truth.contains` 粗糙判定等）纳入测试用例，输出可跟踪的失败证据。

## 3. 测试策略

### 3.1 分层策略

```
单元测试（JUnit5 + Mockito，mock LLMClient/HTTP）   ← 主战场：规则逻辑、状态机、边界
  ↓
集成测试（@SpringBootTest + MockMvc + H2 独立 profile） ← 控制器全端点、DB 持久化、SSE
  ↓
端到端测试（Python/curl 打运行中 8000 端口实例）      ← 真实链路冒烟、超长文本、前端联调
  ↓
回归测试（mvn test 全量 + smoke 脚本，每轮迭代必跑）
```

**关键取舍**：
- LLM 调用是真实付费 API → **单元/集成测试一律 mock `LLMClient`**，只有 E2E 冒烟与超长文本抽样用例走真实 LLM，且限量限轮次（详见第 7 章成本控制）。
- 后端 8000 端口**正在运行且禁止 `spring-boot:run`** → 集成测试用 `@SpringBootTest(webEnvironment = RANDOM_PORT)` 独立起测试实例（不占用 8000）；E2E 打现网实例但使用独立 session_id，避免污染现网会话。

### 3.2 优先级定义

| 级别 | 定义 | 处理要求 |
|---|---|---|
| **P0** | 核心链路、安全、数据完整性、需求硬性要求（超长文本） | 本轮必须补测，阻塞发布 |
| **P1** | 重要功能、状态机、降级路径 | 最近两轮内补测 |
| **P2** | 边缘功能、外部服务、纯 record | 有资源时补测 |

### 3.3 成本控制（LLM token）

1. 测试默认模型 `deepseek-v4-flash`（`AppConfig` 默认值）；批量压测前在 `application-test.yml` 配低配模型或 mock。
2. E2E 真实 LLM 用例：单会话最多 30 轮；超长文本主用例走 mock（见 LONG-01 设计）。
3. 每次 E2E 运行前后记录 `/api/state`，核对会话数，防止泄漏会话堆积。

## 5. 分层测试设计

### 5.1 单元测试（JUnit5 + Mockito）

- **对象**：无 IO 或可 mock IO 的纯逻辑类（RouterService 决策、ArbiterService 审批、Compressor、Validator、Conversation 策略、Track 组件、MovementConstraint 等）。
- **方式**：`mock(LLMClient.class)` 返回固定短文本；规则逻辑直接断言。
- **命名**：镜像主包路径，`XxxTest.java`，沿用现有风格（如 `engine/hooks/RouterServiceHooksTest`）。
- **命令**：`& "C:\Users\shuweiran\AppData\Local\maven\apache-maven-3.9.8\bin\mvn.cmd" test -Dtest=XxxTest`

### 5.2 集成测试（@SpringBootTest + MockMvc）

- **对象**：全部 Controller（含 5.1 之外的服务装配）、DatabaseService、SSE。
- **方式**：`@SpringBootTest(webEnvironment = RANDOM_PORT)` + `@AutoConfigureMockMvc` + `@ActiveProfiles("test")`；`LLMClient` 用 `@MockBean`。
- **DB 持久化**：DatabaseServiceTest 用真实 H2 跑 CRUD、5000 条日志批量插入（见 LONG-02 单元前置）。

### 5.3 端到端测试（现网 8000 实例）

- **对象**：真实链路（SessionController → RouterService → LLM → SSE/前端）。
- **方式**：Python 脚本（UTF-8）+ requests；冒烟用例清单见 5.5；超长文本见第 7 章。
- **冒烟脚本**：`scripts/smoke/smoke_basic.py`（见附录 A）。

### 5.4 回归测试

- 每轮迭代结束跑 `mvn test` 全量（84 + 新增），保证 0 failure。
- 前端改动后：`npm run build` → 产物同步 `static/` → 手动回归第 6 章第四域 P0 用例。

## 7. 超长文本稳定性测试（需求硬性要求）

> 设计原则：**mock 优先、真实 LLM 限量**。三个用例分别覆盖三条超长路径：① 单会话上下文累积；② 持久化日志量；③ 压缩/摘要链。**LONG-01 为必做项**，LONG-02/LONG-03 为补充项。

### 7.1 LONG-01：单角色 10 万字上下文稳定性（必做，主用例）

| 项 | 内容 |
|---|---|
| 目标 | 单会话上下文累计 ≥ 10 万字（约 500 轮 × 200 字），验证不 OOM、不卡死、响应时间可接受、早期内容不丢失 |
| 前置 | 测试用 H2 库；LLMClient 走 **mock**（固定 50 字回复，避免 500 轮真实 token 成本）；`-Xmx512m` 起步（默认堆即可，用于暴露内存问题） |
| 参数 | 轮数 500；每轮 user 消息 200 字（重复 200 字模板 + 轮次序号）；agent mock 回复 50 字；总注入 ≈ 12.5 万字 |
| 步骤 | ① 编写 `LongTextStabilityTest`（`@SpringBootTest` + mock LLM）：`POST /api/init` 建 1 角色会话 → 循环 500 次 `send`；② 每 50 轮记录：`Runtime.totalMemory-freeMemory`、单轮耗时（上下文构建段单独计时）；③ 第 1 轮消息含唯一标记词（如"锚点词XYZ"），第 500 轮 send 后断言模型侧上下文/记忆检索仍能命中该词（经 MemoryStore/Compressor 检索路径）；④ 全程无 `OutOfMemoryError`、无卡死（每轮 < 10s，mock 下应 < 1s） |
| 通过标准 | ① 无 OOM/无 500 错误；② P95 单轮耗时 < 10s，且上下文构建耗时随长度近似线性（无指数爆炸）；③ 锚点词可检索命中（内容不丢失）；④ 堆内存增长有界（后 100 轮与中段涨幅 < 30%，Compressor 生效）；⑤ 结束后 `GET /api/state` 会话状态完整 |
| E2E 抽样版 | 真实 LLM 冒烟：30 轮 × 200 字，jcmd 记录堆，验证响应流畅（真实成本约 30 轮 × 1.5k token，可接受） |
| 脚本思路 | 见附录 A `stress_long_context.py`（E2E 版）；单元版直接在 JUnit 内循环，不加网络层 |

### 7.2 LONG-02：对话日志 5000+ 条持久化稳定性

| 项 | 内容 |
|---|---|
| 目标 | 会话日志 5000+ 条（单会话 2000 + 多会话 3000），验证 History 列表/详情/load 不超时、不丢数据 |
| 参数 | 总条数 5000+；每条 100–200 字；单会话 2000 条连续 |

### 7.3 LONG-03：摘要链超长（Compressor + EavesdropSummarizer）

| 项 | 内容 |
|---|---|
| 目标 | 连续 50 轮压缩/摘要（每轮 20 条消息→1 条摘要→入 MemoryStore），摘要链累计 5 万字，验证无栈溢出/无 OOM、摘要保留关键要素 |
| 参数 | 压缩轮数 50；每轮输入 20 条 × 200 字；每轮输出摘要 ≤ 500 字（压缩率 ≥ 50%）；EavesdropSummarizer 输入 10 万字单条 |
| 步骤 | ① `CompressorTest`：构造 50 轮链式压缩，每轮断言摘要含"说话者+主题+情绪基调"三要素，记录压缩率；② `EavesdropSummarizerTest`：LLM 失败时规则降级摘要处理 10 万字输入（验证截断上限与耗时）；③ 全程捕获 `StackOverflowError`/`OutOfMemoryError`；④ 第 50 轮后断言 MemoryStore 容量受控（≤ 配置上限） |

| 脚本思路 | JUnit 内完成；如需观测真实 LLM 摘要质量，E2E 限量 5 轮（真实摘要调用） |

### 7.4 通用执行与观测工具

- **堆观测**：JVM 参数 `-Xlog:gc`（测试实例）或 `jcmd <pid> GC.heap_info`（现网实例）；Windows 上 `jps -l` 找 pid。
- **脚本语言**：一律 Python 3（UTF-8）；requests 超时设为 60s；批量轮次间 sleep 0.2s 防打爆现网实例。
- **结果记录**：脚本输出 JSON（轮次、耗时、堆、错误码）到 `docs/test-results/`，作为验收证据。

`stress_long_context.py` 核心思路（示例）：

```python
# -*- coding: utf-8 -*-
import json, time, requests, sys

BASE = "http://localhost:8000"
def post(path, body):
    r = requests.post(BASE + path, json=body, timeout=60)   # json= 自动 UTF-8
    r.raise_for_status(); return r.json()

sid = post("/api/init", {"characters": [{"name": "小明", "persona": "健谈"}],
                         "scene": "默认场景"})["session_id"]
marker = "锚点词XYZ-0001"
t0, times, sizes = time.time(), [], []
for i in range(500):                                        # LONG-01: 500 轮
    msg = ("测试消息第%04d轮。" % i) + ("长文本填充" * 40)   # ≈200 字/轮
    if i == 0: msg = marker + msg
    t = time.time()
    post("/api/send", {"message": msg})                     # 实测需带上 session 路由参数
    times.append(time.time() - t)
    if i % 50 == 0:
        print(f"round={i} p50={sorted(times)[len(times)//2]:.2f}s "
              f"max={max(times):.2f}s elapsed={time.time()-t0:.0f}s", flush=True)
        # 可选: jcmd <pid> GC.heap_info 由外部脚本并行采样
print("P95=%.2fs" % sorted(times)[int(len(times)*0.95)])
```

> 注：真实调用 `/api/send` 需核对 SessionController 的会话路由方式（当前实现为单例 router + ConcurrentHashMap 会话表，按 `session_id` 区分），压测脚本按实际请求格式调整；单元级 LONG-01 不依赖此细节。
