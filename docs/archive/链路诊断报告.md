# 非 2D 聊天模式后端诊断报告

## 一、当前消息流程（非 2D 模式）

```
用户选角 → ScenePage.start() → enterScene()
  → api.startScene("default", "me,小百合,小桃", "me")
  → POST /api/scenes/{id}/start?agents=me,小百合,小桃&me=me
  → SceneController.startScene()
    → 拆 agents 为 ["me", "小百合", "小桃"]
    → 每个建 Persona(name)，setPersonaDesc(name + "，一个角色")
    → router.initSession(sessionId, personas, sceneId, "free", "", "")
    → agents.clear() + 添加新 Agent

用户输入 "你好" → 回车 → ChatPage.send()
  → addAgentMsg 乐观显示
  → store.sendMessage("你好", "me")
    → set(isRunning=true) + 启动 polling（每2秒loadState）
    → api.send("你好", "me") → POST /api/send
      → SessionController.sendMessage()
        → router.runRound("你好", null)
          → 遍历 agents，对每个建 LLM 上下文
          → 调 LLM API → 收集 agent_outputs
          → 返回 RoundResult { agent_outputs, narration, ... }
    ← HTTP 200 返回（含 agent_outputs）
    → 【我的修复】遍历 agent_outputs 渲染到 UI
    → set(isRunning=false), 停 polling
```

## 二、问题清单

### 🔴 P0 — Persona 丢失（当前直接症状）

**文件：** `SceneController.java:107-108`

```java
Persona p = new Persona(name);
p.setPersonaDesc(name + "，一个角色");   // ← 永远用占位符
```

LLM 收到的上下文是：
```
【角色小百合】小百合，一个角色
```

没有 personality、background、voice，LLM 不知道要扮演谁 → 退化成通用 AI 助手回复。

**修复方案：** `startScene` 创建 Persona 时查角色库拿真实数据。
- `CharacterController` 里有 `characters` 列表，每条含 `{name, persona, background, voice}`
- 按 name 匹配后取 `persona` 字段填入 Persona
- DB 那边 `CharacterEntity` 也有相同结构

### 🟡 P1 — SSE 广播死代码

| 组件 | 状态 |
|------|------|
| `SSEController.java broadcastAgentOutput()` | 定义了但 RouterService 从不调 |
| `SSEController.java broadcastRoundComplete()` | 同上 |
| `SSEController.java broadcastError()` | 同上 |
| `useSSE.ts` 30+ 事件监听 | 后端没事件 emit，全空 |
| `App.tsx` SSE handler 20+ case | 接收端存在但发送端静默 |

**影响：** 当前消息走 HTTP 返回体直接渲染（我加的），SSE 路径永不触发。要清理的话有两条路：
- **A)** 删掉全部 SSE 机制（`SSEController.java` + `useSSE.ts` + `App.tsx` SSE handler）
- **B)** 让 `RouterService.runRound()` 调 `sseController.broadcast()`，走通 SSE

### 🟡 P2 — 前端双路径消息投递（我造的）

**文件：** `appStore.ts sendMessage()`

```javascript
// 路径1：HTTP 返回体（我加的）
const result = await api.send(text, playerName);
if (result.agent_outputs) {
    result.agent_outputs.forEach(out => store.addAgentMsg(...));
}
set({ isRunning: false });
stopPolling();

// 路径2：polling（每2秒 loadState，从不触发消息更新）
startPolling();
// SSE 事件（永不触发）
```

要么走 HTTP 返回体（路径1），要么走 SSE（路径2）。两条同时跑等于绕一圈。

### 🟢 P3 — 旧构建产物残留

`static/assets/` 下有 5 个旧 hash 的 `.js` 和 `.css` 文件，`index.html` 只引用最新的。

### 🟢 P4 — `setMode` 副作用

`appStore.ts setMode()` 在 mode 切换时设置 `werewolfPhase: 'day_discussion'`，导致非狼人杀模式 loading 文本也显示"☀️ 白天讨论中"。已用 `store.mode === 'werewolf'` guard 屏蔽了症状。

## 三、修复优先级

1. **P0 — Persona 真实数据注入**（当前 bug 的根因）→ 后端 `SceneController.startScene` 加 character lookup
2. **P1/P2 二选一** — 清理 SSE 死代码或撤回 HTTP 返回体路径
3. P3 — 删旧 hash 文件
4. P4 — `setMode` 里非狼人杀模式不要设 werewolfPhase
