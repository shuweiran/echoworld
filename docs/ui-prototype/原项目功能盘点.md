> 用途：为「原 UI vs 新 UI 重设计」查重查遗漏提供客观对照基线。

## 一、技术栈摘要

- **后端**：Java 21 + Spring Boot 3.4 + Maven + Spring Data JPA，H2 数据库（生产 file `./data/roleplay`，测试 mem），Java 21 Virtual Threads 并行执行 LLM 调用；LLM 走 DeepSeek API（OpenAI 兼容，`LLMClient` 统一封装，mock LLM 用于测试）；另有 Brave Search（`/api/search`）、Edge TTS/CosyVoice/Qwen-TTS 语音、MCP 客户端（web-search server）、Pony 文生图（`/api/ai-image` 立绘 + `/api/image` 对局美术）。
- **前端**：React 18 + Vite + Zustand（`frontend`，构建产物同步 `static/`）。当前入口为 `demo2/App2.tsx`（P-0815-F 方向 1 定案）：6 个主页面（模式选择/剧本选择/角色库/剧本生成/狼人杀/设置 + Gal Demo）+ 对局页（`GameBridge` 分流到 ChatPage 整机版 / GalGeneralView / PhaserSimulationView）。旧版整机应用与旧页面（ScenePage/MaterialPage/LoginPage 等）已按引用普查确认死代码并删除（P-0815-F）。
- **通信方式**：REST（JSON）为主渲染通道 + SSE 实时推送（`/api/events` 全局事件流 + `/api/simulation/events` 2D 世界快照流；SSE 支持 `?session_id=` 定向过滤，P-0802-I/D-028）；无 WebSocket/STOMP，无自定义 WS 协议。
- **2D 渲染**：Phaser 3.90（锁 v3 稳定线）渐进替换自研 Canvas（D-020，三阶段全闭环）；后端 Java 权威模拟 + 前端纯渲染，数据流为 SSE/REST 推送状态。
- **架构核心**：每 tick `SimulationOrchestrator` → `WorldDirectorService`（规则目标）→ `InteractionDetector`（TrackScore，阈值 40）→ `TrackDirectorService`（轨道分配 MERGED/WEAK/ISOLATED）→ `MovementConstraint`（聚集/听觉带/避让，含 GroupAnchor leader+follow 队形）→ `ConversationGroup` → `TrackStrategy`（隔离上下文）→ LLM → SSE。

## 四、核心业务流

### 4.1 剧本杀六态状态机（SETUP → INVESTIGATION → DISCUSSION → VOTE → REVEAL → ENDED）

```
触发者/端点                          状态变化                            关键机制
POST /api/script/init              → SETUP（概略剧本+角色分配+秘密+roleKey+地图注册 map_1）
  └ POST /api/script/generate_full → 完整剧本+地图（两阶段第二阶段，异步，script_ready 推送）
  └ (mode=chat 时 init 直进)       → DISCUSSION 自动启动讨论引擎（无取证无地图，D-033）
POST /api/script/advance (DM)      → INVESTIGATION（玩家搜证）
POST /api/script/search            → 搜证：探索地点必得全部未持有可搜线索；扣 AP（各线索 ap_cost 之和）
                                        AP 不足整次拒绝；公开线索不耗 AP；transfer_clue 讨论阶段可转交
POST /api/script/advance (DM) 或阶段超时 → DISCUSSION（startDiscussion 复用）
POST /api/script/start_discussion  → 后台虚拟线程驱动讨论引擎（每局独立 ConversationManager：
                                        持秘密角色轨道=WEAK（EavesdropSummarizer 摘要），未持=MERGED（全文）；
                                        SpeechGate 发言门控：规则触发必发言/阈值打分静默；
                                        人类发言权豁免 discussion_say 直注；讨论结束自动进 VOTE）
POST /api/script/advance (DM) 或讨论结束 → VOTE（enterVotePhase 统一计时 voteStartedAt）
POST /api/script/vote              → 投票；resolve 时惰性判定：超时（默认 60s）未投=弃票+托管；
                                        quorum 不足（有效票<ceil(在线/2)）首次清票重投，重投仍不足→lowParticipation
POST /api/script/resolve           → REVEAL：D6 精确判定（mostVoted==killer_id 机器对比例，平票清票重投）
                                        → D7 审批门挂起（approval.timeout-seconds 默认 60s 超时自动驳回回滚）
                                        → 批准后揭晓（murderer/correct/truth/票型），script_reveal 推送
POST /api/script/finish (DM/前端按钮) → ENDED：confirmEnded 幂等，落库 type=result（玩家/凶手/票型/真相/讨论摘要）
POST /api/script/restart           → 新局（同剧本主题同玩家，复用 sessionId，新剧本/roleKey/票型）
POST /api/script/leave             → 中途退出：角色托管（trustees），票作废、不计 quorum
POST /api/script/resume            → 断线重连：内存命中直接返回 / ScriptEntity type=snapshot 快照重建（重启后可用）
```
阶段守卫：search/castVote/resolveVote/startDiscussion/startVoting 均按 phase 拒绝越界；ENDED 为幂等终态不越界。阶段切换五处（initGame/startDiscussion/startVoting/resolveVote/confirmEnded）无条件发 SYSTEM 级公告横幅（script-phase-broadcast 总开关）+ script_phase/script_status SSE 定向推送。私聊（/api/script/private）、美术（/api/image/*）、逻辑链（/api/debug/trace）为对局内平行功能，不参与状态机。

### 4.2 狼人杀自动闭环（autoPlay 自动推进，D-025）

```
POST /api/werewolf/init（玩家+AI 补满 8 人）→ 注册 RouterService + 人类玩家 + autoPlay 开关
夜间：WerewolfAiPlanner 纯规则行动器（狼共刀不刀狼/预言家验随机存活/女巫首夜救被刀者（witch-save-probability）
      AI 猎人死亡自动反杀）→ 人类 night_action 提交 → resolve_night 结算（werewolf_night_result 定向推送；
      女巫先获知被刀者 witchInformed + werewolf_witch_info 定向推送）
白天：讨论接对话引擎（独立 ConversationManager + TrackStrategy 全员 MERGED + SpeechGate 门控 + 人类发言权豁免）
      → 讨论结束自动 start_voting
投票：AI 投票（村民随机非己/狼队共投非狼）+ 人类 vote → resolve_vote（D7 审批门保留，auto-approve-ms 默认 3000ms
      自动批准，0=等 DM 手动）→ 回夜循环 → 胜负判定（werewolf_game_over）
断线重连：POST /api/werewolf/resume（session_id/room_code + player + player_key 必填防冒充）
状态快照：7 个状态变更点全量落 ScriptEntity type=snapshot（name 前缀「对局快照:ww:」）
```

### 4.3 一般模式会话（自由/主角/多轨/导演）

```
POST /api/init 或 POST /api/scenes/{id}/start → 建会话（characters/scene/mode/protagonist）
POST /api/round/start {turns} → RouterService.runRound（serial=true 串行调度（D-024/D-027）：
      按轨道×角色顺序逐个 LLM 生成，后发言者上下文含前者本轮发言，agent_output 逐个即时推送）
  → TrackStrategy（混合轨道上下文隔离 MERGED/WEAK/ISOLATED）
  → Arbiter 审批（sanitizeSummaryForArbiter 脱敏）→ 压缩摘要 → round_complete SSE
玩家发言：POST /api/send 或 /api/round/suggest 候选话术 → 下一轮
导演模式：无玩家角色，AI 自己对话（DirectorDrawer 手动注入目标 POST /api/goals）
历史：GET /api/history* 查看；POST /api/history/load/{id} 恢复会话；POST /api/round/rollback 回滚
中断：POST /api/interrupt / /api/stop（hard/soft/state，CancellationToken 链路，TaskCancelledException 走既有分支）
```

### 4.4 2D 模拟（Phaser 渲染 + 后端权威模拟）

```

每 tick → SimulationOrchestrator
  → WorldDirectorService（想做什么：规则目标，零 LLM）
  → InteractionDetector（TrackScore 阈值 40：size/bystander/conflict/secret/emotion）
  → TrackDirectorService（轨道分配 MERGED/WEAK/ISOLATED）
  → MovementConstraint（怎么移动：MERGED 聚集质心+GroupAnchor leader+follow 队形 / WEAK 听觉带 / ISOLATED 避让；
     玩家手动目标 60s 保持不被覆盖；导演模式禁控提示）
  → ConversationGroup → TrackStrategy（隔离上下文）→ LLM → SSE world_snapshot（/api/simulation/events）
玩家交互：点击移动（/move）、WASD 持续移动（/move-dir）、点角色对话（/send）、加入/离开对话组
  （/group/{id}/join|leave）、播放完毕信号（/playback_done 点击驱动对话）
演讲广播：AI PUBLIC_SPEAKING → HearingSystem.countHearingListeners 声学判定 → 有听众=area 演讲 / 无听众=global 公告
  （fallback-to-global 可配）；玩家 POST /api/announcements 发公告 → announcement SSE → 横幅+公告栏
```

## 六、鉴权与会话说明

1. **邀请码登录（弱鉴权，默认关闭）**：`POST /api/auth/verify` 校验邀请码（预置 `DEFAULT2024`；`roleplay.auth.invite-enabled` 默认 false → 403「邀请码功能未启用」）；`GET /api/auth/me` 用 Bearer token；admin 端点（generate/list/deactivate）需 `X-Admin-Key`。**项目全局无完整用户体系/注册/密码**——邀请码只是可选的登录门，大多数游戏端点（/api/init、/api/script/*、/api/werewolf/*、/api/rooms/*）无需登录即可调用。
2. **剧本杀 roleKey 令牌（C3/D-017）**：initGame 为每玩家生成唯一 UUID（playerKeys），`toMap` 仅向本人暴露 `role_key`；玩家级端点（status/search/transfer_clue/vote/private/discussion_say/leave 等）支持可选 `player_key` 认证（有 key 校验匹配→错 403；无 key 向后兼容按玩家名）；`GET /api/script/keys` 供 DM 分发；`resume` 强制 key（game_id/room_code 三选一定位 + player_key 认证）。防冒充与重连一体化。
3. **狼人杀 roleKey（P-0802-J/D-029）**：initGame 每玩家 roleKey（toMap 本人可见）；`resume` 三参强制 key 校验；`GET /api/werewolf/keys` 主持人分发。玩家级端点（night_action/vote/discussion_say）暂无 key 校验（按玩家名定位，防冒充留后续）。
4. **DM key 越权保护（C4/D-018）**：`roleplay.game.dm.key` 配置非空时，`GET /api/script/dm/status` 与 `POST /api/script/advance` 要求 `X-DM-Key` 请求头匹配否则 403；默认空=放开（与审批门同模式）。前端 DM 面板提供密码输入框（存 localStorage）。
5. **审批门（D7）**：非传统鉴权——剧本杀揭晓/狼人杀结算挂起等待 `POST /api/approval/approve|reject`，DM 面板可见 pending 载荷；超时自动驳回回滚。
6. **会话定位**：一般模式默认单例 RouterService + SessionRegistry 多会话（session_id 定向，D11）；剧本杀/狼人杀按 session_id 内存对局 + 快照重建；SSE 连接按 `?session_id=` 过滤定向事件（P-0802-I/D-028/029）。
7. **无 WebSocket**：断线重连 = roleKey + 快照恢复（REST），无「新连接顶旧连接」概念。
