## 1. 布局总览（三栏 + 可隐藏侧边栏）

```
┌───────────────────────────── 顶栏 64px ─────────────────────────────┐
│ 🕵️雾港迷案 | 第2轮 | 阶段徽章 | 🎯当前目标徽章 | … | 📜backlog | ⚙️ ❓ │
├──────────┬──────────────────────────────────────────┬──────────────┤
│ 左栏      │                                          │  右栏         │
│ ◀ 折叠钮  │              中栏（主区，自动加宽）          │  » 折叠钮    │
│ 阶段进度  │       阶段核心操作（随页不同）               │  线索 / 逻辑链│
│ 角色列表  │                                          │  / 角色库/历史│
│ (心锁标记)│                                          │  (4 Tab)     │
│ 240px    │               flex:1                     │  280px       │
└──────────┴──────────────────────────────────────────┴──────────────┘
 浮动按钮 📋（仅右栏收起时，右下角半透明）    💾 视图状态已记忆（左下角小字）
```

### 1.1 左栏：图标条收窄模式（icon rail）
- 默认**展开 240px**（评审可见完整布局）；左栏顶部「◀」折叠按钮（相位色描边 + 发光，新手可发现）
- 点击收窄为 **56px 图标条**：阶段图标（🔍💬🗳️）/ 角色图标（圆形首字，角色渐变底色）/ 证据袋图标 🔎 竖排，仅图标 + hover 右侧 tooltip
- 再点「▶」恢复展开；收起时中栏自动加宽
- 依据（见 §3）：隐藏导航可发现性减半（NN/g），左栏采用**收窄而非完全隐藏**，关键阶段/角色信息始终可见

### 1.2 右栏：抽屉模式
- 默认**展开 280px**；右栏顶部「»」收起 → 右栏消失、中栏加宽，右下角出现**悬浮圆形按钮 📋线索**（半透明、置底不挡操作）
- 点悬浮按钮 → 右栏以**覆盖式抽屉**弹出（fixed 定位 + 阴影 + 毛玻璃），再点关闭
- 收起后右侧 4 Tab（线索/逻辑链/角色库/历史）信息不丢失，随时可唤出

### 1.3 视图状态记忆（localStorage）
- 每页独立存储键 `ui-proto-view-v2`（JSON 按页面名分存 `{left, right}`），刷新后恢复展开/收起状态
- 页面左下角常驻小字「💾 视图状态已记忆（localStorage）」示意
- 三张默认状态一致：左栏展开 + 右栏展开；折叠态通过点击演示

### 2.1 排除清单（及理由）

| 排除项 | 来源 | 排除理由 |
|---|---|---|
| 快进 / 自动播放 / 存档读档 | 视觉小说通用 | **多人实时共享进度**：快进/自动播放会撕裂不同节奏玩家的同步；存档读档与「对局状态由后端权威维护」矛盾（本项目后端已有快照/重连体系，前端原型不重复设计） |
| 实时言弹弹幕 | 弹丸论破 | **并发冲突**：多人同时打出言弹会互相覆盖当前论点焦点，且实时弹幕需要低延迟通道；**降级为「引用反驳」**（把对方发言收为个人弹药，异步使用） |
| 全局好感度 | 逆转裁判/恋爱 VN | **单局收益低**：剧本杀单局 1-3 小时、以推理判定胜负，全局好感度跨局累积成本高、对判定无影响；仅在**私聊迷你环节**保留局部好感暗示（P2 后备） |

## 3. 侧边栏可隐藏：3 种模式对比与选择

| 模式 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| A. 完全隐藏（汉堡菜单） | 侧栏内容收进 ☰，点击弹层 | 主区最大 | **可发现性大幅下降**：NN/g 研究结论——隐藏导航使内容可发现性约减半（用户不知道功能存在，使用率显著下降）；多一层点击 |
| B. 完全隐藏 + 悬浮按钮 | 侧栏收起后靠悬浮按钮唤出 | 主区大、入口可见 | 仍有两级心智负担（先找按钮→再找内容）；对「证据袋」「角色库」等高频查看对象不友好 |
| **C. 收窄/抽屉混合（本方案）** | **左栏收窄为 56px 图标条（图标常驻可见）+ 右栏收起为悬浮按钮抽屉** | 左侧关键信息（阶段/角色）**始终可见**，仅牺牲文字；右侧低频但重要的证据库用抽屉随取随用；主区收益：中栏 240+280=520px 全释放 | 图标条需 tooltip 补偿（已实现 hover 提示）；右栏抽屉覆盖主区时遮挡右侧内容（覆盖式，点开即关） |

**选择理由**：
1. **引用 NN/g「隐藏导航可发现性减半」**：左栏承载的是「游戏进程 + 角色状态」这类**高频监控信息**，若完全隐藏，玩家会遗漏阶段切换与角色在线状态——因此左栏采用**收窄不隐藏**（icon rail），信息永远在视口内；
2. 右栏承载「线索/逻辑链/角色库/历史」**低频但容量大**的信息，用抽屉 + 悬浮按钮平衡主区空间与可达性；
3. 两栏收起合计释放 520px 主区宽度，搜证地点网格 / 讨论对话流 / 投票嫌疑人卡均可获得更宽松的布局；
4. 折叠按钮视觉强化（相位色描边 + 发光 + title 提示），规避「新手找不到」风险。

## 4. 落地优先级顺序

> 依据：每项对「可玩性 → 可演示性 → 工作量」的综合性价比排序；对应本项目后端能力（已具备搜证/AP/讨论引擎/投票判定）逐项对齐。

1. **证据袋 + 出示证据**（逆转裁判）——核心推理交互，工作量最低、演示效果最直观；三张右栏线索 Tab 已就绪，仅加「出示」动作
2. **引用反驳（言弹）**（弹丸论破）——复用对话流现有气泡，加按钮 + 弹药条即完成；为讨论阶段注入"反击"策略深度
3. **阶段时间轴**（左栏步骤条）——三栏骨架的骨架，V1 已有，V2 保留并强化（含心锁/被质询状态标记）
4. **关系矩阵**（Obra Dinn）——逻辑链 Tab 从文字链升级为矩阵，数据同源（线索×人物归属），纯前端展示层改造
5. **心锁**（逆转裁判）——依赖「证据-角色」对应关系，在矩阵数据就绪后加锁标记成本极低
6. **演出**（VN 对话框打字机 / 拍案震屏）——锦上添花，放在功能骨架之后；CSS/JS 动画与业务解耦，可独立迭代
