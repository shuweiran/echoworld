## 二、逐条详述

### P0-1｜me 玩家身份误识别（✅ 真实）

**① 描述核对**：真实。新建角色名为 `me` 时，选中该角色会被系统当作「我自己」（玩家身份/导演角色），并触发身份锁定类逻辑。

**② 根因（三层）**：

- **前端 a —— 玩家名默认值 = "me"**：`appStore.ts:147` `currentPlayer: localStorage.getItem('playerName') || 'me'`。从未设置过玩家名时，玩家身份就是字面量 `"me"`。
- **前端 b —— me 卡与角色卡同名冲突**：`ScenePage.tsx:447-470` 渲染「Me 角色卡」（`toggleCharacter(currentPlayer)`），同时角色网格也渲染库中名为 `me` 的角色卡（`toggleCharacter(ch.name)`）——两者操作的是**同一个 selected Set 条目 `'me'`**，无法区分「玩家身份」与「角色 me」。
- **前端 c —— hasMe 导演锁定**：`ScenePage.tsx:182-186`：
  ```tsx
  const hasMe = selectedNames.includes(currentPlayer);
  if (hasMe && mode !== 'werewolf') {
    await setMode('director', '', currentPlayer);
  }
  ```
  选中含 `me` → 进 director 模式、directorCharacter='me' → ChatPage `:741` `store.agents.includes('me') ? 'me' : ''` → 输入框提示「以 me 的身份发言」（`:763`）。
- **后端 d —— 2D 世界硬编码**：`SimulationService.java:34` `private static final String PLAYER_AGENT_NAME = "me";`，`:188-189` 任何名字为 `me` 的角色 `setPlayerControlled(true)`（实测 `/api/simulation/state` 中 agent "me" 的 `playerControlled:true`）。`:438` 玩家控制角色跳过 AI 生成、`:541` 被归入玩家组。
- **后端 e —— 历史消息硬编码**：`RouterService.java:283` `new Message(Message.Role.USER, "me", narration)`——所有用户输入在历史里都以 `me` 为发言人，与名为 `me` 的角色消息完全混淆。
- **后端 f —— 身份参数丢失**：`SceneController.java:169-180` `startScene` 接收了 `@RequestParam String me` 但**从未读取**，且 `initSession(..., "free", "", "")` 恒以 free/空身份初始化（实测当前会话 `mode:"free"` 但 `director_character:"me"`——前后端身份状态已漂移）。

**③ 修复建议**（前端为主，后端需授权）：
1. 前端：新建角色/玩家名校验，禁止使用保留名 `me`（或提示改名）；me 卡与角色卡同名时去重并提示。
2. 前端：`ScenePage.tsx` me 卡输入改名时同步校验；hasMe 判断改为「只有玩家明确把自己设为角色时才进导演模式」。
3. 后端（非禁动）：`SimulationService.PLAYER_AGENT_NAME` 改为配置项或按显式标记（而非名字）判定玩家角色。
4. 后端（禁动）：`RouterService.java:283` 用户消息发言人改为「玩家/主控」避免与角色同名混淆——**涉及 RouterService，需主人授权**。

**④ 优先级确认**：P0 ✓

### P0-2｜No active session 错误 + me 发消息变主控（✅ 真实）

**① 描述核对**：真实，两部分均成立。

**② 根因**：

**(a) "No active session"**：
- 抛出点：`RouterService.java:196-200` `if (!running || agents.isEmpty()) { sse.broadcastError("No active session"); return RoundResult.error("No active session"); }`。
- `running` 只在 `initSession`（L117）/`loadSession`（L149）置 true，`/api/stop`（L178）置 false 后**无任何路径恢复**（runTurns/runRound 均不会）。
- 前端触发链：
  1. 轮询完成判定是**死代码**：`appStore.ts:493` `if (data.router?.phase === 'idle')` —— Java `GET /api/state` 返回**顶层** `status`，无 `router` 包装、无 `phase` 字段 → 该分支永不命中 → 轮询无法自行解除 isRunning；
  2. SSE 正常时靠 `round_complete` 解除；SSE 断开（服务重启/网络抖动，8000 刚重启过）时 isRunning 卡死（只有 900s 超时兜底 `appStore.ts:514`）；
  3. 此时用户发消息 → `ChatPage.tsx:732-734` `if (store.isRunning) { await store.stop(); }` → 后端 `running=false` → `api.send` → runRound → **"No active session"**（SSE error 事件 → 前端「错误：No active session」）；
  4. 之后 `running` 一直为 false，只有**重新进场景**（触发 initSession）才恢复 —— 与「之后恢复」现象吻合。
- 另一候选触发：`agents.isEmpty()`（路由未初始化时直发消息）。两者共用同一守卫。

**(b) me 发消息变主控**：
- `SessionController.java:115-123` `/api/send` **只读 `text`，完全忽略前端传来的 `player_name`**（前端 `client.ts:73` 传了 `{text, player_name}`）。
- `RouterService.java:277-288`：用户输入恒走 `arbiter.classifyUserInput/processUserInput` → 生成主控旁白 → `Message(USER, "me", narration)` 存历史 → `broadcastUserInput(narration, userCategory, "", roundCount)` **character 参数恒为 ""**。
- 前端 `App.tsx:88-107`：`director_speech`/`human_discussion` 分支要求 `data.character` 非空才挂到角色，character="" → 落到 `addUserMsg` → 显示为「主控输入」。
- 附带缺陷：`ChatPage.tsx:749-752` 乐观渲染先 `addAgentMsg(playerName, text)`（若 me 是 agent），随后历史/SSE 又显示「主控输入」→ 同一条消息双重展示、角色归属矛盾。

**③ 修复建议**：
1. 前端（关键）：`appStore.ts:493` 改为 `data.status !== 'running'`（Java 顶层字段）判定回合完成。
2. 前端：`ChatPage.tsx:732` 改为「运行中时不阻塞发送，直接追加输入」，或 stop() 后 send 前对后端做一次恢复性处理。
3. 后端（非禁动）：`SessionController.sendMessage` 支持 `player_name`——若命中 agent 名单 → 该 agent 强制发言（对齐剧本杀 SpeechGate 点名语义）；否则主控旁白。
4. 后端（禁动）：runRound 失败时若 `agents` 非空可自动恢复 running（或返回明确「会话已停止，请重新进入场景」）。**涉及 RouterService/SSE 主链路，需授权**。

**④ 优先级确认**：P0 ✓

### P0-3｜直接进 2D 模拟卡住 + 新开页面 + 内嵌模式无聊天框（✅ 真实）

**① 描述核对**：真实。三部分：卡住、window.open 双开、Phaser 内嵌无聊天框。

**② 根因**：

**(a) 直接进 2D「卡住」**：
- 入口：`ScenePage.tsx:189-200` `start()` 勾选「进入 2D 模拟」→ `enterScene` + 写 localStorage + `window.open('/simulation.html')`。
- legacy 页 `static/simulation.html:739-790` `autoLoadFromApp()` **只 POST /api/simulation/load-characters，从不调用 startSim()**（startSim 在 L543-544，需手动点 Start 按钮 L83）。
- 结果：角色加载进世界但世界不 tick —— 实测 `GET /api/simulation/state` → `{"running":false,"tick":0,"agentCount":5}` → 角色静止、无对话，即「卡住无法进行」。

**(b) window.open 双开**：三处窗口打开（均为渐进式迁移遗留的「原版窗口」设计）：
- `ScenePage.tsx:200`（use2D 勾选进场景时）；
- `ScenePage.tsx:569`（Phaser 内嵌视图上的「🪟 原版窗口（回退）」按钮）；
- `ChatPage.tsx:394`（剧本杀面板「打开 2D 模拟」按钮）。
- 原页面 `view='chat'` 即轨道模式聊天框（带 强链/弱链/隔离 轨道标签），用户认为无需另开窗口 —— 合理诉求。

**(c) Phaser 内嵌模式无聊天框**：
- `PhaserSimulationView.tsx` 只有控制条（场景选择/开始/暂停/重置）+ canvas + 状态文案，**无任何聊天输入**（对照 legacy `simulation.html:110-113` 有 chat-input + 发送按钮，走 `POST /api/simulation/send/{agentName}`）。
- 内嵌模式 `autoStart=true`（L18 默认）会自动 start，故内嵌不卡，但无法对话。

**③ 修复建议**：
1. 前端：ScenePage `start()` 的 use2D 路径改为「进场景后自动开内嵌 Phaser 视图」（复用 `openPhaserSim`），不再 window.open；或至少 window.open 前先 `POST /api/simulation/start`。
2. static（禁动）：`simulation.html` autoLoadFromApp 末尾补 `await startSim()` —— **static/ 属禁动，需授权**。
3. 前端：`PhaserSimulationView.tsx` 增加聊天输入（调 `/api/simulation/send/{name}`，复用 legacy 端点，后端零改动）。
4. 前端：剧本杀面板「打开 2D 模拟」改为内嵌。

**④ 优先级确认**：P0 ✓

### P0-4｜狼人杀模式未进入（✅ 真实）

**① 描述核对**：真实。选狼人杀开始后完全没有游戏流程，仍在按普通对话交流。

**② 根因**：

- **后端狼人杀是手工驱动状态机**：`WerewolfService.initGame`（L~195）只分配角色、`phase=NIGHT`，之后需要人工调 `/api/werewolf/night_action`、`resolve_night`、`start_voting`、`resolve_vote` 等 admin 端点推进——**没有任何自动回合循环、没有任何阶段自动切换**。
- **AI 角色从未进局**：`WerewolfController.init`（L~40-60）只收 `player_name` + `human_players`；前端 `ScenePage.tsx` startWWGame 传的是 `human_players=roomPlayers`（未建房时为空数组），**5 个选中 AI 角色只进了 Router（场景 agents），从未进入狼人杀 GameState**。
- **实测铁证**：`GET /api/werewolf/status?player_name=me` → `{"phase":"night","round":1,"alive":["me"],"your_role":"villager",...}` —— 1 人局、全员村民、永久卡在 night。
- **无 SSE 推送**：`SSEController.java` 只有 script_* 广播方法，**无 werewolf_* 任何广播**（D-013 已记载「前端 werewolf_* 监听器是先行建的死监听」）→ 前端 App.tsx 的 `werewolf_phase/werewolf_player_update/werewolf_my_role` 分支永不触发。
- **roleConfig 参数被静默丢弃**：前端 `ScenePage.tsx` 高级选项的狼人/预言家/女巫/猎人/村民配置以 `&wolf=1&seer=1...` query 传入，但 `WerewolfController.init` 未声明这些 @RequestParam，Spring 直接忽略。
- **前端自动玩是普通对话**：`ChatPage.tsx:690-699` 狼人杀 autoPlay → `startRound(1)` → `/api/round/start` → 普通 runRound 对话（Arbiter 用 GM 提示词而已，`ArbiterService.java:64-78`）→ 「仍按一般模式交流」。
- 前端 startWWGame 的 raw `fetch` 不检查 `res.ok`，init 失败被静默吞掉。

**③ 修复建议**（狼人杀后端属禁动，需专门派单 + 主人授权）：
1. 前端：init 时把选中角色一并传入（body `players` 或扩展 human_players 语义），并检查 fetch 响应。
2. 后端：补 werewolf_* SSE 推送（对齐 script_* 模式）+ 自动回合调度（或由前端驱动 night_action/start_voting 等 API）。
3. 前端：夜间行动/投票 UI（当前完全没有调用夜间/投票端点的组件）。

**④ 优先级确认**：P0 ✓

### P0-5｜剧本杀生成剧本后仍在选人界面（⚠️ 部分真实）

**① 描述核对**：部分真实。生成剧本后确实停留在选人界面、未自动进入游戏——但这是**两步式设计**：`genScript` 生成后明确提示「点『开始游戏』进入对局」（`ScenePage.tsx:338` 状态文案），需再点一次 `startScript` 按钮（L757）。`startScript` 链路（createScene → enterScene → setMode('script') → loadHistory → scriptStatus）**实测可用**：8000 上已存在一个进行中的对局（`GET /api/script/status?player=me` → phase=investigation、6 玩家、角色/秘密/AP/线索齐全）。

**② 根因**：
- UX 流程问题：生成（`api.scriptInit`，LLM 30-60s）成功后仅 setScriptGame + 卡片展示，不自动开局；卡片+地图卡都在同一长页下方，入口不醒目。
- 真实缺陷（次要）：`startScript` 中 `enterScene` → `SceneController.java:180` `initSession(...,"free","","")` 把后端 mode 重置为 free、清空 directorCharacter，随后前端再 `setMode('script')` 补回——前端 store 与后端存在窗口期不一致（功能可用但脆弱）；同时 `router.setScriptGame(game)` 在 `/api/script/init` 时就注册了，enterScene 的 initSession 不清除 scriptGame（侥幸不冲突）。

**③ 修复建议**（前端 UX 批次）：
1. 生成成功即自动调 `startScript()`（或加显著「🎮 进入对局」按钮置顶）。
2. 剧本卡/地图卡折叠化，减少页面长度。
3. 可选：后端 startScene 支持透传 mode（避免 free 覆盖），但涉及禁动链，建议仅前端处理。

**④ 优先级确认**：P0（体验型，可考虑随前端批次处理）

### P1-6｜场景删除报错 + 角色无单个删除（✅ 真实）

**① 描述核对**：真实（删除报错 100% 复现）；角色删除入口存在但同样报错，ScenePage 角色卡确实无删除。

**② 根因**：
- `client.ts:35` `return res.json();` —— request() 对**所有响应**（含 DELETE）无条件 JSON 解析。
- 后端 DELETE 返回 200 **空 body**：`SceneController.java:139-142` `return ResponseEntity.ok().build()`；`CharacterController.java:113-116` 同样。
- → 空响应体被当 JSON 解析 → 浏览器抛 `Failed to execute 'json' on 'Response': Unexpected end of JSON input` → 前端 catch 显示错误。
- 角色删除：**后端端点存在**（`DELETE /api/characters/{name}`），**UI 入口存在**（`SettingsPage.tsx:356` 角色库每角色删除按钮 + L97-105 deleteCharacter），但同样踩空 body 解析 bug 而报「删除失败」；**ScenePage 场景设置的角色网格确实没有任何删除入口**（只有点击选中 + 右键编辑）。

**③ 修复建议**（小改动批次，前后端皆非禁动）：
1. 前端（一处修复全好）：`client.ts` request() 对 204 或空 body（`content-length:0`）返回 `null`，或 try-catch 兜底 `res.text()` 判断空。
2. 后端（更稳）：DELETE 返回 `ResponseEntity.ok(Map.of("status","deleted"))`。
3. 前端：ScenePage 角色卡补「删除」按钮（对齐 SettingsPage）。

**④ 优先级确认**：P1 ✓

### P1-7｜角色语言（TTS）无声音（✅ 真实）

**① 描述核对**：真实。开启角色语音后完全没有声音。

**② 根因**（后端是占位实现）：
- `TtsService.java:74-77`：
  ```java
  // TODO: Actual TTS integration
  // Edge TTS: edge-tts --voice zh-CN-Xiaoxiao ...
  return "/api/voice/audio/placeholder_" + System.currentTimeMillis() + ".mp3";
  ```
  合成返回**占位 URL**（该路由不存在，前端请求必 404）。
- `SSEController.java` **没有任何 tts_start/tts_chunk/tts_end/tts_error 广播方法**（全文件 grep 无 tts 字样）→ 前端 App.tsx 的 tts_* 监听（L~200-220）与 `ttsPlayer.ts`（解码 base64 MP3 播放）**管线完备但永远没有数据源**。
- `VoiceController.java` 只有语音识别（/transcribe，Whisper STT）+ status/start/stop，无 TTS 端点。
- 前端 ChatPage 的 🔊/🔇 角色语音开关（L~640-650）只写 `voiceMap`（仅作 tts_start 门控），对不存在的流无意义。

**③ 修复建议**：
- 方案 A（推荐，后端非禁动但 SSEController 涉及）：后端实现真 TTS —— Edge TTS 子进程流式或 CosyVoice API + 在 agent_output 后发 tts_* SSE（需动 SSEController 主链路，**授权后做**）。
- 方案 B（前端独立，零后端）：改用浏览器 Web Speech API（speechSynthesis）直接朗读 agent 消息，voiceMap 控制开关——最快见效。
- 注意浏览器自动播放策略：需用户手势后初始化。

**④ 优先级确认**：P1 ✓
