- 降级版不接 Track/ConversationManager，秘密隐藏退化为"提示词禁令"（讨论 prompt 明确告知"不得泄露你的秘密"，由 LLM 自觉遵守）
- **降级版验收标准**（替代 A3-1~A3-4）：D-3-1 startDiscussion 后 phase==DISCUSSION 且轮流发言消息可获取；D-3-2 讨论消息数 == 角色数 × 配置轮数（默认 2）；D-3-3 轮数耗尽后 phase==VOTE；D-3-4 mock LLM 断言"不得泄露秘密"指令存在于讨论 prompt

### Step 4 判定与落库修补（🔴P0）— 解 GAP-4（D6 + 关键事实 B）

**做什么**
1. **truth 判定加固（killer/truth 职责分离）**：剧本 schema 增加凶手实体 `killer` 字段——**killer 是机器对比例（角色名精确匹配），truth 保留为人类可读叙述文（如"管家张三在书房用烛台杀害了主人"）**，两者职责分开：`resolveVote` L239 的 `truth.contains(mostVoted)` 改为实体比对 `mostVoted.equals(killer)`（只比对 killer 字段，不再扫描 truth 文案）
2. **平票缺陷修复**：L241–246 平票时不再无条件设 winner；方案选型（默认**平票重投**：清空 votes、phase 回 VOTE、round++；备选：平票转 REVEAL 且 winner 置空）——开工前先定案，避免验收断言漂移

## 四、验收标准（可测试断言级别）

> 测试环境约束：LLM 一律 mock（G1 LLM 401 阻塞，见第六章）；断言可在后端 JUnit（@SpringBootTest + mock LLMClient）与前端手动/组件测试执行。

### Step 1 秘密机制
- A1-1：mock LLM 返回含 secrets 的剧本 JSON → `initGame(sessionId, theme, [p1,p2])` 后 `getGame(sessionId).secrets` 非空，且 secrets 键集合 == roles 集合
- A1-2：`/api/script/status?player=p1` 的 toMap 含 `your_secret`，且值 == p1 所分配角色的秘密；**p1 的视角不含 p2 角色的秘密**（对 p2 同理断言）
- A1-3：LLM 抛异常走 defaultScript 兜底时，同样产生非空 secrets（兜底路径不漏机制）
- A1-4：`InteractionDetector.evaluate(agents, secretTaskAgents)`（L73）传入持秘密角色集合时，集合内角色的 TrackScore 含 SECRET_TASK（+50）贡献；集合外角色不含

### Step 2 前端主链路
- A2-1：client.ts 存在且**仅存在** 8 个 script* 方法，路径/请求体/响应体与调研报告⑤契约表逐一吻合（含 `/api/script/generate` 挂在 SessionController）
- A2-2：ScenePage 输入主题 → 点「AI 生成剧本」→ scriptJson 非空（L494 死代码区开始渲染）；点「加载剧本并开始」→ 进入游戏页并显示 your_role
- A2-3：游戏页流程：选地点 → scriptSearch 响应线索上屏；投票 → scriptVote；揭晓 → scriptResolve；状态栏随 scriptStatus 轮询更新（参照 WerewolfStatePanel）
- A2-4：grep 前端 `剧本杀模式正在开发中` 零命中（占位文案清除）；`scriptJson` 出现位置中 setter 存在（L35 修复）

### Step 3 讨论接对话引擎
- A3-1：`startDiscussion` 后 `getActiveGroups()` 非空（产生讨论组）且 game.phase == DISCUSSION
- A3-2：持秘密角色在讨论轮次收到的上下文只含摘要（WEAK 分支），**断言注入内容不含其秘密明文**
- A3-3：讨论组 `allFrozen()`（L106）或 `shouldContinue()`（L185）为假 → `startVoting` 可进入 VOTE 阶段
- A3-4：`WorldDirectorService.getGoal(agent)`（L90）对持秘密角色返回注入的目标（如"隐藏秘密"类）

### Step 4 判定与落库
- A4-1：构造边界用例——投票对象 == killer 实体 → correct=true；投票对象名字出现在 truth 文案中但 ≠ killer → correct=false；近似名 → false
- A4-2：平票（votes={a→b, c→d} 两平）→ winner 不被设置（game_over 语义正确）；按所选方案断言：重投则 phase==VOTE 且 votes 清空、round 递增
- A4-3：对局结束后 `ScriptRepository.findAll()` 非空（saveScript 已调用落库，含 contentJson 可反序列化）
- A4-4：判定流程结束后 phase == ENDED（终态触达）

### Step 5 审批门
- A5-1：触发审批节点后 `ApprovalService.getStatus(sessionId)`（L134）== PENDING
- A5-2：`approve` 后游戏流程继续（下一阶段可执行）
- A5-3：不响应直到超时 → 状态为拒绝（L72–79 超时自动拒），流程按拒绝路径走

## 六、风险与依赖

1. **G1 LLM 401 环境阻塞（问题清单 G1，硬阻塞）**：真实 LLM 不可用，所有依赖真实生成的断言在现网不可跑。对策：验收断言一律 mock LLMClient（参考问题清单 A1 台账 #1b 的 mock 实践）；真实对局人工验收延后至 key 修复。
2. **ConversationManager 依赖 SimulationWorld/Agent 实体（Step 3 最大适配风险）**：`ConversationManager.init`（L57）需要 `SimulationWorld + Function<String,Agent> agentLookup`，而剧本杀没有 world 实体——需把角色名单适配为 AgentState/Agent。**建议 Step 3 开工第一天先做 spike 验证**（角色名单 → 最小 Agent 适配是否可行）；若适配成本过高，降级方案：**每个角色按 assignments 顺序轮流输出一条讨论消息（轮数可配置，默认 2 轮，结束后自动进 VOTE）**——行为定义与降级版验收标准（D-3-1~D-3-4）见 Step 3，全量对话引擎 P1 再补。
3. **TrackStrategy 语义适配风险**：`supportedMode() = GROUP_DISCUSSION`（L87）、`prepareContext/processResults`（L92/L137）面向模拟世界 agent；剧本杀"轮流发言 + 隐藏身份"语义是否兼容需 spike 验证；WEAK 摘要可能丢关键讨论信息（如指向凶手的线索），需在 A3-2 断言外另加"关键线索不丢失"人工用例。
4. **狼人杀链路：可照抄 vs 需新写**（调研报告⑥）：
   - **照抄**：发起流程（startWWGame L170–188）、WerewolfStatePanel（ChatPage L150）、阶段横幅（L523–528）、真人等待输入（L596–600）、消息可见性过滤（L309–311）、SSE 分支模式（L109–181）、client 封装模式、controller 会话管理（playerSessions+currentSessionId，ScriptController L18–19 已同构）
   - **需新写**：搜证交互（狼人杀无对应环节）、线索面板、讨论入口（狼人杀讨论走聊天，剧本杀讨论要接对话引擎）、揭晓演出
5. **双生成器 schema 不一致（①1.2 vs ①1.1）**：`/api/script/generate` 返回的剧本无 secrets/killer——Step 2 预览若展示秘密会缺失；Step 4 加 killer 时两处 schema 都要同步改，否则预览与实际对局剧本不一致。
6. **initGame 只返回第一玩家视角（L156）**：多玩家时各自视角依赖 `/api/script/status?player=`（L73）；前端 init 后须按玩家名分别拉 status；本地单机演示建议固定玩家名，避免 getOrDefault 落到 currentSessionId 串台（L40/L62/L75）。
7. **落库与历史体系割裂**：剧本杀不产生 RouterService 会话，HistoryPanel（L129）已预留 script_ 前缀剥离但无数据来源；若要把剧本杀对局纳入历史（P2）需额外接线；另注意 D12 历史加载缺陷（问题清单）若未修复会波及历史类验收。
8. **平票方案选型影响验收断言**：Step 4 开工前先定平票方案（默认重投），避免 A4-2 断言漂移；该决策同步影响前端投票面板的"重投提示"文案（Step 2 若先做需预留）。
