### 1.2 数据流

```
ScenePage(genScript) → POST /api/script/init
  → ScriptController.init: 生成 sessionId + playerSessions 登记 + router.setScriptGame(game)（D5）
  → ScriptGameService.initGame: LLM callJson(600 token) → secrets/clues/locations 解析 → shuffle 分角色
  → 返回 toMap(首玩家视角, 含 your_role + your_secret)
  → 前端展示剧本卡 → startScript: 建 scene(script_xxx) → enterScene → setMode('script') → scriptStatus 轮询

搜证:   ChatPage → POST /api/script/search → ScriptGameService.search（仅 INVESTIGATION, 必得线索）
讨论:   POST /api/script/start_discussion → phase→DISCUSSION + 桥接：
          initWithPersonas(玩家人设) → setSecretAgents(持秘密玩家) → buildDiscussionGoals→setTrackGoal(WorldDirector)
          → simulationService.start() → 2D 世界 ConversationManager/tick 驱动讨论（TrackDirector 强制秘密玩家 ISOLATED）
投票:   POST /api/script/vote → castVote（非法票拦截, 不能投自己）
揭晓:   POST /api/script/resolve → resolveVote：计票→平票重投→resolveMurderer 三级解析
          → approvalEnabled 时挂起 ApprovalService.submitForApproval(60s) → 批准→REVEAL / 驳回→回滚清票重投
状态:   GET /api/script/status?player= → toMap(player)（线索按玩家隔离, your_secret 只发本人）—— 前端每 3s 轮询
```

### 1.3 核心类职责要点

- **ScriptGame.Phase**：`SETUP / INVESTIGATION / DISCUSSION / VOTE / REVEAL / ENDED` 六态名义齐全（`ScriptGameService.java` L53）
- **ScriptGame 内部类**：secrets(role→secret)、assignments(player→role)、playerClues、votes、simulationStarted 等（L55-130）
- **toMap(playerName)**：唯一状态快照出口；your_secret 按角色发放；clues 按 public/playerClues 过滤（L74-88）
- **resolveVote**：D6 判定 + D7 审批门都在此方法（L243-334）
- **ScriptController.startDiscussion**：**桥接编排在 Controller 层**（L68-82），ScriptGameService.startDiscussion 本身仍只改 phase+round++（L514-521）

## 5. 风险点

1. **讨论双通道未定案（N-1）**：最根本的架构未决事项。2D 模拟是官方桥接链路，但聊天页文本通道（带 secret 角色卡）也在 script 模式生效，玩家可绕过/并行于 2D 讨论发言，两通道信息不互通，可能导致"讨论内容对不上"。
2. **Controller 层桥接（N-2）+ 全局单例 SimulationService**：多局并发会互踩（clearAll/全局 secretAgents/goals）；桥接逻辑无测试保护。
3. **ENDED 缺失连带问题**：`game_over` 语义由 `!winner.isEmpty()` 决定（toMap L77），REVEAL 后 game_over=true 但 phase 停 REVEAL，前端"已结束"阶段（SCRIPT_PHASE_LABEL.ended）永不出现；对局状态无终态可判，落库也失去触发点。
4. **审批竞态（N-3）**：前后端 60s 双超时同值，慢网/慢机下前端报错而后端仍在挂起，DM 审批结果与玩家看到的不一致。
5. **测试缺口大**：剧本杀 7 端点无 Controller 集成测试；initGame/secrets 发放（A1 系列）、桥接（A3 系列）均未自动化；当前唯一测试类 ScriptGameServiceTest 只有 6 个用例且只覆盖 D6/D7。
6. **文档失真会误导后续 agent**：TEST_STATUS 12 用例虚标、PROJECT_CONTEXT 前端零接入残留、raw 报告过时、需求文档索引指向已删文件——任何新 agent 按文档开工都会得到错误基线。
7. **内存态游戏（N-6）**：重启即丢、无鉴权、playerSessions 无清理；与狼人杀同构问题（raw 报告已取证）。
8. **判定仍无结构化真凶（N-7）**：truth 文本解析是 D6 的"次优解"（D-010 决策记录"schema 需加 killer 字段，双生成器必须同步"），该决策项尚未落地，LLM 输出不稳时判定可靠性存疑。
