## 0. 结论速览（TL;DR）

1. **贴合度现状**（N §1.1 复核确认）：地图生成时 LLM 实际只能看到 4 类信息 —— theme、locations、clueLocations、请求尺寸。**剧本 background / storyline / truth / 角色人设 / 线索内容均未注入**。rooms 与 locations 对应只靠 prompt 软约束，`MapValidator` 7 项校验**不含**「rooms 覆盖 locations」检查。
2. **尺寸现状**（N §2 复核确认）：生产默认 40×24（= LLM token 预算上限）、测试 24×16；全链路无尺寸下限，`POST /api/script/map` 显式传任意正数尺寸均可生成（8×8 也能出图，BSP 路径只剩 1 个「房间 A」）；LLM 声明尺寸小于请求尺寸时校验仍放行。
3. **P-0810-17 两阶段生成**（D-048 已落地）：init 概略先行 → `generate_full` 后台异步完整生成 + 地图。**地图在 applyScript 之后用完整剧本 locations 生成**（复核确认），故「地图房间 vs 完整剧本地点错位」不会发生；但**概略 vs 完整 locations 无程序化一致性校验**（仅 prompt 软约束）+ **SETUP 期手动调 map 端点会用空 locations**（map 端点无 phase 守卫）—— 这是修正后的真实漂移风险（详见 §2.4 冲突修正）。
4. **核心改进**：**P0 三项**（N）—— ① 剧本上下文（background/storyline/truth）注入地图 prompt（+250-400 tokens 输入，无撑爆风险）；② 校验链加「rooms 覆盖 locations」检查（zones 侧覆盖已由 P-0803-D 闭环）；③ 尺寸下限 clamp + 随地点数自适应放大。P1/P2 见 §3。
5. **历史调研落地状态**（F 核对）：F 的四项调研建议**最小方案已全部落地**（P-0803-D/E + #92 台账）；其 P2 遗留（契约 v2 clue_ids / 分布策略 / 可见性增强 / chunk）与 G 的玩法升级线（roleLocations / GalMapView / 像素贴图）仍为开放待办。

## 1. 现状与能力边界（含代码路径证据）

### 1.1 地图生成链路（现行，两阶段 + 双生成器）

```
POST /api/script/init（outline_only 缺省 true）→ ScriptGameService.initGame 五参重载 outlineOnly 分支
   └─ scriptService.generateOutline(theme, players)  → game.outline / phase=SETUP / toMap 附 outline+generating 键
POST /api/script/generate_full → ScriptGameService.generateFull（discussionExecutor 异步线程）
   ├─ generateScriptChecked(theme, players, outline)   （outline 作 prompt 约束，防两阶段矛盾，D-048）
   ├─ applyScript(game, schema)                        （locations/clues/secrets/AP 全量填充）
   ├─ full 模式 → generateMap(sessionId, "", 0L, false)（LLM→7 项校验→BSP 降级；多图注册表 maps/currentMapId/searchedByMap）
   └─ script_ready(map_ready) + script_phase + script_status SSE
```

- **关键事实**（代码复核，`ScriptGameService.java:618-628, 755-824`）：**地图生成发生在 `applyScript` 之后**，`game.locations` 此时已是**完整剧本** locations（`applyScript` :628-629 `clear + addAll(ScriptSchemaV1.locations(script))`）。→ **地图房间与最终剧本地点天然一致**，N §1.3 所述「地图基于概略 locations 生成、后被完整剧本覆盖导致错位」的机制在现行代码中不成立（见 §2.4 冲突修正）。
- 兼容路径：`outline_only=false`（3/4 参旧重载委托）保持同步完整生成 + 自动地图（`initGame` :620-651）；chat 模式不生成地图（D-033/D-034）。
- 手动端点 `POST /api/script/map`（`ScriptController.java:133-171`）**无 phase 守卫**（D-034 已核实）：SETUP 期可调，但此时 `game.locations` 为空（概略路径不写 locations）→ **空 locations 地图风险**（新增，见 §2.4）。

### 1.2 LLM 生成地图时实际可见的剧本信息（贴合度根因）

`ScriptMapService.buildPrompt`（`ScriptMapService.java:392-481`）注入项仅 4 个（复核确认）：

| 注入项 | 来源（代码复核） | 说明 |
|---|---|---|
| theme | `ScriptGameService.generateMap` effTheme = theme 空 ? game.name : theme（:1011） | 实测「民国宅邸凶案」等，LLM 自行扩写一句 |
| locations | `game.locations`（完整剧本 `ScriptSchemaV1.locations(script)`；概略态为 toMap 附加键） | prompt 要求「rooms[].name / zones 应覆盖这些地点」 |
| clueLocations | `game.clues[].location` 去重（:1052-1055） | prompt 要求「zones[].clue_location 必须逐一取自这里」 |
| width / height | 显式传参 → 对局已定尺寸 → 配置默认（:1009-1010, :1048-1049） | 预算内嵌入 prompt 要求精确尺寸 |

**未注入**：`background`（完整剧本 100-150 字 / 概略 storyline 50-100 字）、`truth`（50-80 字）、`roles[].intro`、`clues[].content`、`killer_id`。（N §1.1；代码复核 buildPrompt 签名 `(theme, locations, clueLocations, width, height)` 无背景参数。）→ 背景故事中的关键场景细节（「书房是案发现场」「暴雨封路」）对地图零影响 —— **贴合度不足根因**。

### 1.3 尺寸链路与配置（全环节）

```
POST /api/script/map body width/height
  → ScriptController.map（:133-171）：只 parseInt，非法→0，无边界校验
  → ScriptGameService.generateMap 7 参（:1002-1021）
      effW = width>0 ? width : (game.mapWidth>0 ? game.mapWidth : mapDefaultWidth)   (:1009-1010)
      mapDefaultWidth = @Value("${roleplay.game.map.default-width:40}")（:181-184）
  → doGenerateAndRegister（:1045-1063）→ mapService.generateMap(effTheme, locations, clueLocations, seed, effW, effH)（:1057）
  → ScriptMapService.generateMap 5 参（:96-216）
      effW = width>0 ? width : BspMapGenerator.DEFAULT_WIDTH(24)（:99-100）
      llmBudgetOk = effW<=40 && effH<=24（LLM_MAX_WIDTH/HEIGHT=40/24，:53-54, :103）
      预算内 → LLM：callJson(buildPrompt(...), 8000, 45)（:119）
      预算外/失败 → BSP：BspMapGenerator.Options.of(seed, effW, effH, -1)（:208-209）
  → BspMapGenerator.Options.of（:41-45）：width<=0 → DEFAULT 24×16
  → game.mapWidth/mapHeight 记实际输出（:1020-1021）→ 快照落库/恢复（:3003-3004, :3120-3121）
```

配置默认值：生产 `application.yml:79-80` = **40×24**；测试 `application-test.yml:54-55` = **24×16**。（N §2.1 复核一致；N 文中的 :72-73/:52-53 为旧行号，键位内容一致。）

**P-0804-H 重要背景**（N 未强调、T/G 佐证、代码复核确认）：**LLM 不再输出 layers 网格**——buildPrompt 明确「不要输出 layers…由程序确定性生成」；LLM 只声明 rooms/zones/spawns/doors/width/height，程序补空白地网格 → `ensureRoomWalls` 确定性围合。因此：
- LLM 输出体量 ≈ **672-1165 tokens**（T §3.2 实测；旧「2500-3000 tokens 网格输出」口径已过时，见 §5 冲突 C2）；
- `layers` 的最终尺寸 = LLM **声明**的 width/height（`MapContract.normalize` :55-56 取声明值，空白网格按声明值生成）→ R2「LLM 收缩尺寸」风险机制成立（见 §2.2）。

### P0-1 剧本上下文注入地图 prompt 【贴合度核心，来源：N P0-1】

- **方案**：`ScriptMapService.buildPrompt` 增加背景段；`ScriptGameService.doGenerateAndRegister`（:1045-1063）在调 `mapService.generateMap` 前取 `game.background`（概略态 = `outline.storyline`，已写入 `game.background` :585）＋ `game.scriptSchema` 的 truth（可空），拼成 `backgroundText` 透传。
- prompt 新增段落（插在剧本主题之后）：「剧本背景（仅用于氛围与场景布置参考，rooms/zones 地点仍以『剧本地点』为准）」＋ 强化「房间名单必须严格覆盖『剧本地点』列表，不得增减」（同时强化 P0-2 软约束）。
- **成本**：background+truth ≈ 200-210 字 ≈ **250-400 tokens 输入**（N §3）；对照现有 prompt 输入 ≈2000+ tokens（T 实测 buildPrompt ~1500+ 字符），增加 ≈15-25%；**输出侧零增量**（LLM 输出 672-1165 tokens、预算 8000，T 实测）。无撑爆风险。
- **改动文件**：`ScriptMapService.java`（buildPrompt 加参/重载 + generateMap 加参）、`ScriptGameService.java`（:1057 调用点）；`ScriptController` 无需动。旧签名委托（`buildPrompt` 3 参重载 :392-393）保测试零破坏。
- **风险**：① 签名变更需同步测试 `ScriptMapServiceTest`；② LLM 可能把 background 中的场景名词写进 rooms → prompt 必须写明「locations 为唯一地点来源，background 只用于氛围」；③ 概略态仅 storyline（50-100 字），贴合度提升有限，属可接受折中。
- **验证**：测试断言 buildPrompt 含 background 文本；真机验证 zone prompt/theme 出现背景元素。

### P0-2 房间-地点覆盖率校验 【贴合度护栏，来源：N P0-2 + F G1-5 承接】

- **方案**：生成后（LLM 与 BSP 路径都做）检查 rooms 覆盖：复用 `matchLocation`（`ScriptMapService.java:253`，同义词宽容匹配）计算 `rooms[].name ∪ zones[].clue_location` 对 `locations` 的覆盖率；缺失地点 → zones 侧已由 `ensureClueZoneCoverage` 兜底（已落地），**rooms 侧**若 LLM 漏输出地点房间 → 记 fallback reason（「LLM 房间未覆盖地点 X」）**不降级 BSP**（房间数 ≠ 地点数不是校验错误，是质量提示），前端可展示。
- 可选强化：`MapValidator.validateMap` 加重载 `validateMap(map, requiredLocations)`，将「rooms 未覆盖 locations」列为 **warning**（不做 error，防误杀语义近似地图）。
- **改动文件**：`ScriptMapService.java`（post-check + reason）、`MapValidator.java`（重载）、测试。
- **风险**：同义词/子串误判（「餐厅」vs「厨房」）；建议仅「差 >1 个地点」时提示，避免噪声。
- **验证**：4 locations 4 rooms 全过；LLM 输出 3 rooms → warning + zone 补齐后搜证可用。

### P0-3 尺寸下限 + 自适应放大 【尺寸护栏，来源：N P0-3；✅ 已裁决（2026-08-10）：选 B——测试 yml 同步改断言，min 32×20 维持】

2. **随地点数自适应**：`effW = clamp(locations.size()×8, 32, 40)`、`effH = clamp(locations.size()×5, 20, 24)`（**限制在 LLM 预算 40×24 内**，避免触发大图 BSP 闸；6 地点 → 40×24）。倍率 8/5 建议进配置或写死并注释（D-004 勿 hardcode 纪律）。

- **验证**：显式 8×8 → 32×20；4 locations 默认 ≥32×20；6 locations → 40×24。
