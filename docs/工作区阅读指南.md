# Roleplay-Java 工作区阅读指南

> 目的：让接手者先看到“当前有效入口”和源码，再按任务读取证据，避免把构建产物、日志、截图和历史台账混在一起阅读。
>
> 更新：2026-08-19，批次 P-0819-B。

## 1. 推荐阅读顺序

1. `AGENTS.md`：协作门禁、禁动范围、测试和台账规则。
2. `docs/并行作业登记.md`：确认当天批次和文件占用。
3. `docs/INDEX.md`：按任务选择专题文档。
4. `PROJECT_CONTEXT.md`：项目目标、当前阶段、核心文件和已知问题。
5. `DECISION_LOG.md`：只搜索与当前任务相关的决策编号，不要通读全文。
6. 按需读取 `TEST_STATUS.md`、`docs/问题清单-20260731.md` 和专题文档。

## 2. 文件分层

### 优先阅读：活跃入口与源码

- 后端源码：`src/main/java/`
- 后端测试：`src/test/java/`
- 前端源码：`roleplay-v4/frontend/src/`
- 构建配置：`pom.xml`、`roleplay-v4/frontend/package.json`
- 当前契约和专题文档：以 `docs/INDEX.md` 的场景索引为准

### 默认跳过：生成物与验证留档

- `target/`、`roleplay-v4/frontend/dist/`：构建产物
- `src/main/resources/static/`、`static/`：部署/静态副本，只有部署或静态资源任务才读
- `logs/`、`*.log`：运行日志，只有排查具体运行问题才按文件和时间读取
- `tmp/`：截图、响应快照、部署备份和一次性证据
- `work/`：CDP、探针和一次性验证脚本；需要复现时按批次读取
- `data/`、`*.mv.db`：运行数据，不作为源码上下文

### 谨慎修改：高耦合或并行敏感文件

- `RouterService`、`ArbiterService`、审批、狼人杀、SSE 主链路
- `docs/并行作业登记.md`、`docs/修改记录.md`、`TEST_STATUS.md`
- 与当天登记批次重叠的文件

## 4. 读取规则

- 大文件优先 `rg -n` 定位，再读取上下文；不要整读 `DECISION_LOG.md`、`TEST_STATUS.md`、`docs/修改记录.md`。
- 先确认并行占用，再修改文件；本批次不得自行 commit。
- 改代码后登记 `docs/修改记录.md`；跑测试后登记 `TEST_STATUS.md`，失败也要如实记录。
- 需要静态资源或验证证据时，按批次从 `static/`、`tmp/`、`work/` 精确取文件，不把整个目录加入上下文。
