## 七、方法说明（判定规则）

### 7.1 范围与编码
- **全量扫描**：`os.walk` 遍历 `D:\roleplay-java`，按扩展名白名单 + 二进制探测（null 字节）识别文本文件；**388 个文件全部逐一统计**，无抽样。
- **编码**：逐文件按 UTF-8(BOM)/UTF-8/GBK 顺序解码，全部 388 个文件均为合法 UTF-8 文本；**无效输入（不可解码/乱码）实测为 0**。
- **快照时点**：统计为 2026-08-03 12:42 时刻的全量快照；扫描期间并行批次 P-0803-A/B 正在写入文档（地图功能可行性调研/输入质量记录等），已包含最终快照内的最新版本。

### 7.2 行分类（互斥优先级：空行 → 关键词行 → 重复行 → 注释行 → 有效内容）
1. **空行**：去除换行符后为空的纯空白行。
2. **纯注释行**：整行均为注释——按语言注释语法（Java/JS/TS 的 `//`、`/* */`、Python 的 `#` 与三引号文档字符串、HTML/XML 的 `<!-- -->`、yml/ini 的 `#` 等）用状态机识别，含跨行块注释；行内有代码的混合行不算注释行。
3. **未完成/占位标记行**：行内命中关键词 `TODO/FIXME/XXX/HACK/TBD/PLACEHOLDER/TO-DO/lorem/ipsum/dummy/占位符/示例填充/待补充/待补/待填/待实现/待完成`（不区分大小写）——对应任务口径「TODO/FIXME/XXX/占位符/示例填充」及其同族标记；**剔除**仅因 HTML/JSX 功能性 `placeholder="…"` 属性命中的行（属功能属性非填充垃圾）。更宽的 占位/示例/填充 任意出现口径（约 280 行/106KB）以描述性用语为主，不作主口径（见第六节提示）。
4. **重复冗余行**：两类——**规则 A**：≥3 个连续非空行组成的相同文本块（块内至少一行 ≥20 字符，防纯结构行误报）在文件内出现 ≥2 次，后续出现计冗余；**规则 B**：注释型纯分隔线（如 `// ----`、`# ===`）同一行文本出现 ≥3 次，第 2 次起计冗余。
5. **有效内容**：以上均不命中的行（代码、正文、数据）。

### 7.3 字节口径
- 各类噪声按「行」归属字节 = 该行去除换行符后按文件编码编码的字节数；**占比 = 类别字节 ÷ 行内容总字节**（4,031,813 B，不含换行符，保证行级分类与字节统计自洽）。
- 磁盘字节（4,127,096 B，含换行符）作为「总输入量」参考值给出；若按磁盘字节计，噪声占比为 16.74%。

### 7.4 局限性与误报风险
- 注释/字符串内关键字（如字符串里的 `//`、`#`）按启发式近似，复杂字符串场景可能误判（影响 <1%）。
- 「占位/示例/填充」宽口径在文档中大量为描述性用语，已改用严格「未完成/占位标记」口径作主统计（宽口径数据见第六节提示）。
- 重复检测只覆盖「完全相同的行/块」，不识别语义重复（不同表述的相同信息）；真实冗余可能略高于本报告数值。
- 纯注释行按任务口径计入噪声；若按「注释=有效文档」口径，噪声占比将降至约 3.5%。
