# 幻境之书桌面版维护与更新流程

> 状态：发布流程已固化；当前仅允许本地验证，**不得发布正式版**。

## 一条原则

发布包只允许来自“本次提交的可执行后端 jar + 版本号 + 更新清单”。任何普通 jar、历史备份 jar、手工替换 jar 都不得进入正式发行物。

## 版本规则

- 采用语义版本：`主版本.次版本.修订`，例如 `0.1.0`、`0.1.1`。
- 破坏存档/API 兼容性时升主版本；新增功能升次版本；修复升修订。
- `0.0.0` 只代表开发态，脚本会拒绝为它生成 `latest.yml`。
- 每个版本必须有对应 Git 标签 `vX.Y.Z`、变更说明和 SHA-256。

## 固定流程

1. 在发布分支完成代码评审、Maven 测试和前端构建；不要触碰正在运行的 8000 服务。
2. 在干净 Windows 构建环境以 JDK 21 生成后端 jar；必须检查 manifest 含 Spring Boot `Main-Class`。
3. 更新 `frontend/package.json` 的版本号，并同步锁文件；新增本版本变更说明。
4. 生成或复用已验证的 `desktop/runtime-release`；它必须含 `java.instrument`，否则 Spring Boot Tomcat 无法启动。
5. 运行 `desktop:prepare-release`，显式传入**本次**可执行 jar 和 HTTPS 更新地址。脚本会拒绝普通 jar、HTTP 地址和陈旧 staging 内容。
6. 执行 `desktop:dist`，得到 NSIS 安装程序、ZIP 与 `.blockmap`。
7. 用 `desktop:update-manifest` 生成 `latest.yml`；将安装包、`.blockmap` 和 `latest.yml` 原样上传到同一个 HTTPS 目录。
8. 先在干净 Windows 用户账户安装并验证启动、存档、卸载；再从上一版本执行一次更新验证。两项都通过后，才允许发布。

## 命令模板

```powershell
cd frontend
npm ci
npm run desktop:prepare-release -- -EngineJar ..\..\target\roleplay-engine-<version>.jar -UpdateUrl https://updates.example.com/huanjingbook/stable
npm run desktop:dist
npm run desktop:update-manifest -- -BaseUrl https://updates.example.com/huanjingbook/stable
```

## 更新目录契约

以下文件必须位于同一 HTTPS 目录，且不得改名：

- `latest.yml`
- `HuanjingBook-X.Y.Z-x64.exe`
- `HuanjingBook-X.Y.Z-x64.exe.blockmap`

客户端安装包内会写入更新地址；也可通过 `ROLEPLAY_UPDATE_URL` 覆盖，仅用于测试或私有部署。应用只在发现更高版本时下载，下载完成后由用户选择重启安装。

## 发布门禁与回滚

- 没有代码签名证书时，发布说明必须提示 Windows SmartScreen 风险；正式公测前补齐 Authenticode 签名。
- 不可覆盖已发布文件。回滚只能重新发布一个版本号更高的修复包，或将 `latest.yml` 指回上一个已验证版本。
- 每次发布保存：Git 标签、变更说明、EXE/ZIP 的 SHA-256、`latest.yml`、测试结果和构建环境版本。
- 更新失败时，用户数据和 `backend.log` 位于 Electron 用户目录；禁止让安装目录承担数据库写入。
