## 一、现状全貌

### 1.1 后端：手工驱动状态机（无自动循环、无 SSE、无落库、无测试）

**文件**：`src/main/java/com/roleplay/engine/service/WerewolfService.java`（约 20KB，仅被 `controller/WerewolfController.java` 调用，全后端无第二处引用；`src/test` 36 个测试文件中**零狼人杀测试**）

**状态机结构**（WerewolfService.java）：
- `Role` 枚举：WEREWOLF / SEER / WITCH / VILLAGER / HUNTER（L40）
- `Phase` 枚举：NIGHT / DAY_DISCUSS / DAY_VOTE / **JUDGMENT（声明但从未使用，死枚举）** / ENDED（L41）
- `GameState`（L43-101）：roles / alive / phase / round / winner + 夜间行动字段（wolfTarget/seerTarget/witchSaveTarget/witchPoisonTarget/已用解药毒药/昨夜死者/猎人可否开枪）+ 投票表 votes + 淘汰记录 eliminated；`toMap(playerName)`（L76-101）按玩家视角脱敏输出（狼人互见、预言家查验证结果、非本人角色不可见）

**各阶段流转与端点（全部手工驱动）**：

| 阶段 | 服务层方法（行号） | 端点 | 触发者 | 说明 |
|---|---|---|---|---|
| 初始化 | `initGame`（L118-145） | POST /api/werewolf/init | 前端 | 只把传入 players 全部列为 alive，按 customRoles 或 `assignDefaultRoles` 分配角色（L147-163），phase=NIGHT、round=1 |
| 夜间 | `recordNightAction`（L176-220） | POST /api/werewolf/night_action | 玩家 | 仅 phase==NIGHT 可执行 kill/check/save/poison 四类行动 |
| 夜间结算 | `resolveNight`（L222-267） | POST /api/werewolf/resolve_night | **admin** | 结算狼刀+女巫毒 → 淘汰 → 胜判定 → DAY_DISCUSS 或 ENDED。**缺陷：猎人夜间死亡只把 hunterCanShoot 置 false（L254-257），并不触发开枪选择，猎人反击需另行调 hunter_shoot** |
| 白天讨论 | （无） | — | — | **没有任何方法**：状态机到 DAY_DISCUSS 即停，等待人工调 start_voting |
| 进入投票 | `startVoting`（L397-402） | POST /api/werewolf/start_voting | **admin** | DAY_DISCUSS → DAY_VOTE |
| 投票 | `castVote`（L276-285） | POST /api/werewolf/vote | 玩家 | 仅 DAY_VOTE、存活者、不能投自己 |
| 投票结算 | `resolveVote`（L287-336） | POST /api/werewolf/resolve_vote | **admin** | 得票统计→平票处理→**D7 审批门**（`awaitVoteSettlementApproval` L338-390，挂起等 DM 审批，超时 60s 驳回回滚保留票数）→ 放逐→胜判定→round++→回 NIGHT |
| 猎人开枪 | `hunterShoot`（L423-441） | POST /api/werewolf/hunter_shoot | 玩家 | 被淘汰猎人可开枪 |
| 强制结束 | `endGame`（L449-451） | （无端点） | — | 无控制器暴露 |

**胜判定**（`checkWinCondition` L406-413）：狼人 0 → villager 胜；狼人 ≥ 村民 → werewolf 胜。

**Controller 层**（WerewolfController.java，约 5.3KB）：
- `init`（L24-52）：收 `player_name` + `human_players` query + body{players, roles}；**未声明 wolf/seer/witch/hunter/villager 任何 query 参数 → 前端职业配置被 Spring 静默丢弃**（E3）；生成 12 位 UUID sessionId；**不返回 session_id、不注册 RouterService、不发任何 SSE**；`currentSessionId` 为单字段（L20-21），后 init 覆盖先 init，多局会串。
- 其余端点仅做参数透传（night_action L54-61 / hunter_shoot L63-70 / vote L81-88 / resolve_night L72-79 / resolve_vote L90-97 / start_voting L99-105 / status L107-114）。

**SSE 实况**：`SSEController.java` **无任何 werewolf_* 广播方法**（全文件 grep 仅 script_* 三个 typed 方法 L146-196）。与 DECISION_LOG D-013 记载一致：「后端此前并无 werewolf_* 实际推送，前端监听器是先行建的死监听」。实测 4 秒 SSE 采样无任何命名事件（仅心跳）。

**LLM GM 是"装饰性"的**：mode='werewolf' 时，ArbiterService 有两处 GM 提示词——
- `configureTracks`（L64-78）：提示词**硬编码「当前阶段：day_discuss / 轮次：1」**，与实际 GameState 完全脱节，且要求 LLM 输出 role_info 自报身份（与真实角色分配可能矛盾）；
- `integrateOutputs`（L290-300）：要求输出 phase/killed/saved/exiled/game_over/winner/next_round 七字段，但 **RouterService.runRound（L341 调用）只取 narration，七字段从不消费**（全文件 grep killed/saved/exiled/game_over 无业务读取）→ LLM 输出的"阶段推进"纯属旁白，状态机纹丝不动。

## 二、为什么进不去游戏（完整因果链）

```
① 前端 startWWGame 传 human_players=roomPlayers（未建房 → 空数组）
        ↓（WerewolfController.init L31-37：body 无 players → 走 human_players 分支 → 空）
② 玩家列表 = 仅 [player_name="me"] 一人 → initGame 1 人局
        ↓（assignDefaultRoles L159-160：n<4 → 全员 VILLAGER）
③ GameState：alive=["me"]、roles={me:VILLAGER}、phase=NIGHT —— 无狼人、无预言家、无女巫
        ↓（实测铁证：GET /api/werewolf/status → phase:night, round:1, alive:["me"], your_role:villager）
④ 5 个选中 AI 角色（苏哲/林诗/老王/小美/阿强）只进了 Router agents（实测 /api/state → agents 5 人）
   —— 从未进入 WerewolfService.GameState（alive 只有 me）
        ↓
⑤ phase=NIGHT 无自动调度：需人工调 admin 端点 resolve_night → start_voting → resolve_vote
   —— 前端没有任何调用（client.ts 只有 init/status；全前端 grep 无 night_action/vote 等）
        ↓
⑥ 后端不发 werewolf_* SSE → App.tsx 7 个监听分支永不触发 → 前端对游戏状态无感知
        ↓
⑦ 用户以为"开始游戏"了 → 实际在普通对话模式：autoPlay 走 startRound(1)
   → POST /api/round/start → RouterService.runRound → Arbiter GM 提示词装饰性输出
   （killed/saved/exiled/phase/game_over 七字段从不消费）→ "仍按一般模式交流" ✅ 与主人反馈完全吻合
```

**附加放大因素**：
- 职业配置（roleConfig）query 参数被 Spring 静默丢弃（WerewolfController.init 未声明 @RequestParam，E3）——即使多人也配置无效；
- startWWGame 的 fetch 不检查 res.ok，init 失败被静默吞掉，用户无任何错误提示；
- 状态机卡 NIGHT 后**无任何超时/自动推进/恢复路径**（对照剧本杀 C3 快照+重连），一旦卡死只能重开。

## 四、重构方案（分阶段路线）

### 阶段 0：最小可玩版 MVP（单人 + AI 对战，能玩通一局）

**目标**：1 真人 + N AI 开一局，夜间 AI 自动行动、白天讨论、投票、结算、胜负展示全自动（或按钮驱动）。

**后端改造点**（全部禁动，需主人专项授权）：
1. `WerewolfController.init`：改为 JSON body `{players:[真人+AI 全量], human_players:[真人], roles?}`；players 全量进 GameState；响应加 `session_id`；注册 `router.setScriptGame` 等价物（若白天讨论需 secrets/身份进上下文）；补 3 个 admin 端点的 session_id 守卫（对齐 ScriptController L44-73 模式）。
2. 新增 AI 夜间行动规则器（`WerewolfAiPlanner`，纯规则）：狼人随机刀非狼、预言家随机验存活、女巫首夜救被刀者/后续毒随机、猎人死亡后随机枪——对齐 D-002「纯规则零 LLM」与 D-004「阈值勿 hardcode」纪律（人数/概率配置化）。
3. `SSEController` 新增 typed 方法：`werewolf_phase` / `werewolf_status` / `werewolf_night_result` / `werewolf_vote_update` / `werewolf_game_over`（对齐 GAP-8 script_*：状态变更点全推，Jackson JSON）。
4. 白天讨论：**首选**复用 D-012 资产（`createScriptDiscussionGroup` + `runScriptDiscussionRounds` + SpeechGate 门控，独立实例避免与剧本杀互覆）；**降级备选** D-009 轮次发言（按序每人 1 条，轮数可配）。讨论结束自动 `startVoting`。
5. 推进节奏：夜间全员行动完成（或真人行动 + AI 自动）→ 自动 resolveNight；白天讨论结束 → 自动进投票；投票全员完成 → resolveVote（**保留 D7 审批门**，批准/驳回走既有 ApprovalController）。

**前端改造点**（非禁动）：
6. `ScenePage.startWWGame`：传 `{players: 选中角色全集, human_players: roomPlayers}`；检查 res.ok；展示 session_id/身份/存活；高级选项职业配置改走 body roles（不再丢 query）。
7. 新组件 `WerewolfNightPanel`：按 `your_role` 渲染行动区（狼人→选刀目标；预言家→选查验；女巫→救/毒选择；猎人→死后开枪选择），调 `werewolfNightAction`。
8. 新组件 `WerewolfVotePanel`：存活玩家 chip 选择投票 + 审批门 pending 提示（批准/驳回）。
9. `client.ts` 补 6 个 API 封装（nightAction / hunterShoot / vote / resolveNight / startVoting / resolveVote）。
10. App.tsx 7 个 werewolf_* 分支从死监听变真消费（骨架已在）；ChatPage autoPlay 改为「等真人行动 → 自动推进」节奏。

**测试策略**：新增 `WerewolfGameSmokeTest`（@SpringBootTest+RANDOM_PORT+H2 mem+mock LLM）：init 全量进局 → 夜间 AI 行动 → resolveNight 死亡结算 → 讨论 → 投票 → resolveVote（含 D7 审批批准/驳回回滚）→ 胜负判定 → 终态；AI 行动器单测（边界：1 狼无村民/全员村民不死）；SSE 推送断言（对齐 ScriptGameEndedTest 模式）。

**风险**：
- 讨论引擎为 service 实例级共享（D-012 已知限制），狼人杀与剧本杀并发讨论互覆世界 → 阶段 0 用独立实例 + 文档声明"同时只开一局讨论"；P1 再改 per-game。
- 审批门阻塞 60s（D-018 已知限制）：无人批则自动驳回回滚 → 单机可配 `roleplay.game.approval.enabled=false` 或前端自动批准。
- 真机部署需 mvn package + 8000 重启（涉"不动 8000"纪律，由主会话/主人执行）。

### 阶段 1：完整版（规则完备 + 联机 + 可运营）

- 规则补全：G1-1 猎人开枪修正、G1-2 女巫首夜信息、G1-3 狼人互认/私聊、平票重投 UI、淘汰观战。
- 可运营：G1-4 对局落库（type=script/result，复用 ScriptEntity，对齐 D-013）+ 终态确认端点（对齐 confirmEnded）+ 重开/退出；G1-5 快照 + roleKey 重连（对齐 D-017）；G1-6 DM 推进/审批 UI（对齐 D-018）；G1-7 联机房 room_code 绑定（对齐 C3 轻量绑定）；G1-8 阶段 SYSTEM 横幅（对齐 D-021）。

## 七、一句话结论

**狼人杀"完全没进游戏"的根因是三重脱节：① 前端 init 只传了真人玩家（AI 角色从未进 GameState，单机退化成 1 人村民死局）；② 后端状态机纯手工驱动且无自动调度、无 SSE 推送（前端对游戏零感知）；③ 前端"自动玩"实际走普通对话管线（LLM GM 输出从不消费）——三者叠加导致用户看到的就是"一般模式交流"。修复 = 阶段 0 最小可玩版（init 全量进局 + AI 夜间行动器 + werewolf_* SSE + 复用剧本杀讨论引擎 + 夜间/投票 UI）约 6.5-9 人日，完整版另加 6-8 人日，全部后端改动涉禁动需主人授权。**
