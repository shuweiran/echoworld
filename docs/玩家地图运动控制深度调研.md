## 3. 前端输入与移动链路取证

### 3.1 输入 → 目标（点击 / WASD）
- 点击：`SimulationScene.ts L284-317` `this.input.on('pointerdown')` → `p.x/p.y` 直接当世界坐标（钳制 [10,990]×[10,590]）→ `callbacks.onSetTarget(me, x, y)` → 组件层 `PhaserSimulationView.tsx L156-162` `fetch POST /api/simulation/target/{agentName}`。
  - **坐标转换正确**：场景无任何相机变换（全文件无 setZoom/setScroll/follow），Phaser 输入已按 ScaleManager 反算游戏坐标，`p.x/p.y` == 世界坐标。实测点击目标 (569,496) 与像素追踪的角色落点吻合。
  - 受控角色解析：`playerName` → 'me'/'我'/'主人'；无玩家角色（导演模式）→ 禁止控制仅提示（L296-308，P-0814-I）。
  - 点击命中 NPC（≤32px）→ 同时触发 `onAgentClick`（对话，P-0813-D），不影响设目标。
- WASD：`SimulationScene.ts L209-214/L1005-1029` 键盘注册，按住时每 **120ms**（MOVE_DIR_INTERVAL_MS）`POST /api/simulation/move-dir/{name}`；与点击互斥（moveActive 时点击被忽略 L286）；聊天输入框聚焦时不响应（L1007）。
- **无虚拟摇杆**（当前只有点击 + 键盘）。

### 3.2 插值与渲染（关键）
- 渲染：`SimulationScene.ts update() L1036-1060`：
  ```js
  const sp = Math.hypot(d.vx || 0, d.vy || 0);
  if (this.running && sp > 1) {
      tx += (d.vx || 0) * dt;   // 速度外推（P-0813-G 为 200ms SSE 间隔设计）
      ty += (d.vy || 0) * dt;
  }
  const k = Math.min(1, (delta / 16.666) * 0.35);   // 每帧向快照收敛 ~35%
  ```
- **R1 根因实锤**：`AgentState.toMap()`（后端 `AgentState.java L145-167`）**从不输出 vx/vy**（全后端 grep `"vx"/"vy"` 0 命中）→ 前端 `sp` 恒为 0 → **外推分支永不执行**（死代码）。角色位置只靠「快照到达 → lerp 收敛 ~115ms → 冻结等下一快照」。
- **广播节流**：`SimulationController.java L63` `if (snapshot.tick() % SSE_BROADCAST_TICK_INTERVAL == 0)`（SSE_BROADCAST_TICK_INTERVAL=2，P-0815-E/F）→ 全量快照 **400ms/2.5Hz**（实测 sseGaps p50=399ms/max=426ms）。每 400ms 周期 = ~100ms 突进 + ~285ms 冻结 → **移动视觉一卡一卡**。
- 数据源双通道：SSE world_snapshot（2.5Hz）+ fetchState 3s 轮询兜底（PhaserSimulationView L307-336）。**无本地位置写入**（前端从不 setPosition 到自算坐标，只 lerp 追快照）→ 排除「自己动又被拉回」。
- 障碍渲染：P-0815-F 签名门控（applySnapshot L668-678），**纯视觉**；碰撞判定全在服务端，前端无本地碰撞预测。

### 3.3 碰撞
- **前端无本地碰撞预测**：点击后角色是否可到达完全由服务端 MovementSystem 决定；撞墙表现为「服务端位置被 clamp/滑行 → 快照回传 → 前端跟随」，无提前减速/贴墙停。

## 4. 后端移动执行链路取证

### 4.1 移动指令端点（SimulationController.java）
- `POST /target/{agentName}` L213-231：设 targetX/Y + hasTarget + **manualTarget=true**（Phase 4 保护标记，约束层不得覆盖）。玩家速度：**90-105 px/s**（playerControlled 分速，SimulationService L344-347，move-speed-player-base=90 + rand 15）。
- `POST /move-dir/{agentName}` L238-266（P-0814-I）：目标 = 当前服务端坐标 + 归一化方向 × step（默认 90px 上限 200），每次刷新 manualTarget 时间戳（防 60s 导演接管）。
- 移动执行：`SimulationWorld.tick()` L226-245 → preTickHooks（MovementConstraint → SchedulerService）→ `MovementSystem.update(allStates, 0.2)`。**玩家与 AI 同一套 tick/同一套力模型**，仅速度不同。

### 4.2 MovementSystem 移动模型（MovementSystem.java）
- 合力 = 目标力 220 + 分离 80 + 凝聚 30 + 对齐 20 + 障碍斥力 200（半径 80px）+ blocked 切向滑行 300；速度钳制 ±moveSpeed，阻尼 0.90/tick（L155-194）。
- **R3 实锤**：`computeForce` L125-143——直线被障碍打断（`obs.intersectsLine`）时施加**固定方向**切向力 `forceX += ny*300; forceY += -nx*300` + 30% 目标力；**切向方向不随滑行自适应**，只要视线仍被挡就持续单向滑。目标在墙内（不可达）→ 永远滑（直到 60s manualTarget 超时）→ **点击墙后角色「滑走」而非停住** = 方向漂移/失控观感。
- 碰撞解决：`clampToWorld` L198-257（P-0813-E）最小穿透边推出 + 二次 clamp → **无抖动**（实测 reversals=0），但也不做「撞墙停」。

### 4.3 玩家目标/位置的写入方（全量 grep）
| 写入点 | 对玩家的行为 |
|---|---|
| SimulationController /target /move-dir | 玩家目标唯一合法写入方 |
| MovementSystem.update | 唯一物理移动方（含对话中 manualTarget 保留行走，L49-63） |
| MovementConstraint.apply L145 | **跳过** playerControlled/manualTarget/inConversation |
| SchedulerService.applyToWorld L184-186 | **跳过** playerControlled/manualTarget/inConversation/occupied |
| SimulationOrchestrator（P-0815-E） | **跳过** playerControlled（不生成目标/不分配轨道） |
| WorldDirector goals | 经 orchestrator 过滤，玩家无目标 |

→ **玩家的目标/位置不会被任何导演/日程/约束系统覆盖**（D-006/P-0813-E/P-0815-E 全部落地），排除「目标被重置」。

### 4.4 对话冻结
- `MovementSystem.update` L49-63：对话中 **无 manualTarget → vx=vy=0 冻结**；有 manualTarget → 继续走向目标（P-0813-E 语义：玩家指令优先于对话站位）。玩家在对话中点击 → manualTarget=true → 仍可移动。→ 对话不构成移动锁（与主人澄清一致，非对话锁问题）。

### 4.5 tick 与快照频率 → 端到端延迟链
```
点击 → POST /target（4-5ms 实测）
     → 服务端下一 tick 生效（≤200ms，均值 ~100ms）
     → MovementSystem 开始移动（90-105px/s）
     → SSE 广播（tick%2==0，≤400ms，均值 ~200ms）
     → 前端 applySnapshot → lerp 首帧（~16ms）
```
- **点击→画面动 ≈ 300-700ms**（实测 A 三轮：tServerMove 99-149ms、tVisual 306-695ms；tVisual 受 100ms 截图采样粒度限制，真实下限≈首快照到达+lerp 首帧）。
- 移动中视觉滞后：快照间隔 400ms × 90px/s ≈ 36px/周期的阶梯，lerp 突进-冻结循环。

## 6. 根因结论（按证据强度排序）

1. **R1（已修复）：快照缺 vx/vy → 前端速度外推死代码 + 2.5Hz 广播节流 = 移动一卡一卡/不跟手主因。**
   证据：AgentState.toMap 无 vx/vy（代码直证）→ SimulationScene.update `sp>1` 分支永不执行（代码直证）→ A/B 实测滞后减半（实测）。修复 = 后端 2 行，激活 P-0813-G 已就绪的外推代码，零前端改动。
2. **R2：点击移动纯服务端回显、无本地预测 → 点击→画面动 300-700ms。**
   证据：延迟链代码推导 + 实测。需客户端预测（点击即本地移动 + 快照校准）才能根治；或降低广播间隔/玩家高频通道。
3. **R3：撞墙/墙内目标 → 切向滑行单向持续滑离 = 方向漂移/失控。**
   证据：MovementSystem blocked 分支代码 + C 组实测（36.6px/400ms 持续滑离、hasTarget 恒 true）。需「目标不可达 → 就近可达点或停止」判定。
4. **R4：WASD 实际速度低于配置（67-79 vs 90-105）**：加速斜坡+阻尼+tick 量化，手感偏慢（低优）。
5. **排除项**：渲染帧率 60fps 健康（非卡顿来源）；点击坐标转换正确；无位置回写互搏；玩家目标不被导演/日程/约束覆盖；对话冻结不影响手动目标（确认非对话锁问题）。
