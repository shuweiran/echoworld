> 调研日期：2026-08-15（主人反馈「玩家角色依旧很难受控」，P-0815-E 已落地后复测）

## 0. 结论摘要（TL;DR）

P-0815-E 把 **「AI 系统替玩家做决策」** 这条线（导演目标/轨道分配/约束/日程）已经基本堵死（证据强度高，逐文件核实）。但玩家实测仍「难受控」的根因不在编排器，而在 **「对话系统把玩家锁进自动对话」+「点击语义混杂」** 这条线上：

1. **根因一（高概率）：「自动对话锁」**——玩家发一条消息（或点击 NPC 触发自动打招呼）→ 后端自动建 DYAD 对话组 → 玩家角色 `inConversation=true` + 速度清零（冻结）；组内 AI 在玩家不发言时仍会连说最多 6~10 轮（前端播放完毕自动发 playback_done 持续推进）；期间玩家新消息全部被路由进**旧组**（wakeGroupForAgent），无法与新 NPC 开启新对话；组内无人可自动解散的路径（有玩家成员的等待组不超时解散）。玩家的角色要么被冻结在原地，要么被「AI 一直缠着说话」。
2. **根因二（高概率）：「点击移动」与「点击 NPC 开对话」耦合**——任何 32px 内命中 NPC 的点击（包括玩家只是想走过去的点击）都会同时：设移动目标 + 触发 Gal 对话 + 自动以玩家身份发问候 → 自动建 DYAD → 触发根因一的锁。
3. **根因三（中概率）：玩家消息超距滞留**——自动 DYAD 有 200px 距离门，玩家在空旷处发言（最近 AI > 200px）不建组，消息永久滞留在 `currentMessage`（无消费、无清除、无提示），玩家「说了没人理」。
4. **根因四（中概率）：控制反馈延迟**——SSE 快照节流 400ms + 服务端 tick 200ms + WASD 指令 120ms 一次，点击/按键到画面可见响应的最坏链路 ≈ 600ms，表现为「不跟手」（P-0815-F 已修渲染卡顿，数据通道延迟仍在）。
5. **根因五（低-中概率）：导演模式（未带玩家）下前端仍把第一个角色当玩家操作**——`resolveMeName`/点击标记清除逻辑残留 `names[0]` 兜底（一处），且后端此时没有任何角色是 playerControlled → 玩家以为在控制、实际控制的是被 AI 全权接管的 NPC。

**一句话**：玩家角色「不被 AI 控制」这件事已基本做到；但「玩家自己的指令（移动/发言）能干净地生效并随时收回」还没有做到——自动对话的粘性把玩家钉在了对话态里。

## ① 控制链路全景图（文字版）

### A. 移动控制链路（2D 探索模式）
```
前端点击画布 (SimulationScene.pointerdown, 命中判定 32px)
  ├─ 命中 NPC → onAgentClick → Gal 对话面板 + 自动打招呼（见链路 B）
  └─ 无论命中与否 → 解析"受控角色"(playerName→'me'/'我'/'主人') → POST /api/simulation/target/{me} {x,y}
前端 WASD (SimulationScene.update, 按住 120ms 一次) → POST /api/simulation/move-dir/{me} {dx,dy}
后端 SimulationController.setTarget/moveDir
  → AgentState.setTargetX/Y + hasTarget + manualTarget=true（时间戳刷新）
  → 世界 200ms tick (SimulationWorld.tick)：
       preTickHooks: MovementConstraint.apply（跳过 playerControlled/manualTarget/inConversation）
                     SchedulerService.applyScheduleWindows（跳过 playerControlled/manualTarget）
       MovementSystem.update：非对话 → 目标力(220)+绕行(300) 移动；
                              对话中+manualTarget → 仍移动；对话中+无 manualTarget → vx=vy=0 冻结
  → SSE world_snapshot（每 2 tick=400ms 节流广播）→ 前端 applySnapshot → 位置插值渲染（速度外推+35%收敛）
```

### B. 发言/对话链路（2D 探索模式）
```
SimGalChatPanel 输入 → POST /api/simulation/send/{me}（simSend）
  → SimulationService.sendUserMessage：currentMessage 写入 + wakeGroupForAgent（不在组→false）
  → 下一 tick ConversationManager.tick：
       玩家有 pending 消息且不在组 → 找 200px 内最近 AI → 自动建 DYAD 组（startGroup）
       → 玩家 inConversation=true + 冻结；AI 生成回复（LLM 2-15s）
  → executeRound：玩家消息先入 messageHistory（recordTurn）→ AI 上下文可见 → AI 回复
  → world.addConversationEntry(recentConversations) → SSE（附 recentConversations）→ 前端 worldMsgs → GalStore 队列打字机播放
  → 队列排空 → useAutoPlaybackDone（enabled=!!groupInfo）→ POST /api/simulation/playback_done {group_id}
  → 组循环 awaitPlayback 唤醒 → 下一轮（AI 继续发言；玩家沉默则跳过，最多 6-10 轮后组解散）
玩家想退出：点「🚪 退出对话」→ leave API（组移除玩家，组解散或 AI 继续）→ inConversation=false 解冻
```

## ④ 修复方案建议（最小改动优先）

### Fix 1（RC2，纯前端，改动最小，收益最大）：点击 NPC 不再自动发言
- **方案**：`PhaserSimulationView.handleAgentClick` 去掉自动 `send` 问候行（保留开面板 + 系统提示「你走近了 X，在输入框说话即可开始对话」）；对话由玩家**主动输入**触发（输入 → send → 自动 DYAD，链路保留）。
- **影响面**：仅 2D Gal 面板交互；后端零改动；DYAD 触发条件从「点击即触发」变「发言即触发」，语义更干净。
- **风险**：低。需要玩家多一步输入（本来也要输入才能聊）；防抖表 greetTsRef 可一并删除。
- **备选**：若主人想保留「点击即开聊」，可改为「点击 NPC 开面板但不自动发消息，面板内出现『💬 打招呼』按钮，点击才发问候」。

### Fix 2（RC1，后端最小）：对话锁自动释放
三个子方案，按改动量排序，可组合：
- **Fix 2a（推荐，最小）**：`DyadStrategy.shouldContinue`（及 TrackStrategy 默认策略）增加「玩家连续沉默即结束」——组内含玩家成员且**连续 2 轮玩家未发言** → 返回 false 结束对话（组解散、玩家解冻）。语义：AI 说完该说的就停，不再自言自语。
  - 影响面：仅 2D 世界对话节奏；AI-AI 组不受影响；测试需补 1-2 例。
- **Fix 2b（推荐）**：`ConversationManager.tick` 解散逻辑扩展——组含玩家成员时，若**玩家距组最近成员 > MAX_AUTO_DYAD_DISTANCE（200px）且玩家当前无 manualTarget** → 把玩家移出组（调 leaveGroup 同款还原逻辑，组内 AI 继续或自然解散）。语义：走远了对话自动断。
  - 影响面：ConversationManager 一处；leave 语义复用；风险低。
- **Fix 2c（可选）**：玩家发起移动（/target 或 /move-dir 置位 manualTarget）时自动 leave 当前组——「移动=离开对话」直觉语义。需在 SimulationController 两个端点加一行委托；注意与「对话中可移动（P-0813-E）」语义冲突，**不建议**（会破坏「边走边聊」）。

### Fix 3（RC3，后端最小）：玩家消息超距滞留提示 + TTL
- 超距不建组时，向玩家发一条 system 提示（复用 world 消息通道或 SSE 独立事件：「附近没有人听到你的话，走近一些再试试」），消息保留在 currentMessage 等玩家走近后自动建组（不丢输入）。
- 同时给 currentMessage 加 TTL（如 60s 未消费自动清空 + 提示），防永久滞留与主控 prompt 污染。
- 影响面：ConversationManager.tick 一处 + 前端 system 行消费（worldMsgs 通道已有）；风险低。

### Fix 4（RC4，P2 优化）：移动回显延迟
- SSE 节流改为「按需」：玩家角色 hasTarget/manualTarget 时快照每 tick 推（或仅位置变化推），静止时维持 2 tick 节流。改动在 SimulationController 广播逻辑，风险中低。
- WASD step（90px）与 tick（200ms × 90-105px/s ≈ 18-21px/tick）对齐：step 减小到 ~40px 或按速度计算，减少「按住时目标永远在前方」的锯齿感。低优先。

### Fix 5（RC5，前端小）：统一删除 names[0] 兜底
- `SimulationScene.update()` L1055 的点击标记清除逻辑删 `|| names[0]`（与 pointerdown 的导演模式守卫一致）；`resolveMeName` 的 names[0] 兜底改为仅在显式 withPlayer 语义下使用（或移除并提示）。
- 影响面：导演模式 UI 一致性；风险低。

### 不做（建议）
- **不做全局「对话中禁止移动」**：P-0813-E 特意让玩家移动优先于对话站位，方向正确，保留。
- **不做自动 DYAD 距离放宽**：P-0815-A 的 200px 门防「玩家在角落被拉进 1v1」，保留，用 Fix 3 提示替代。
