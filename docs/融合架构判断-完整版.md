| 模块 | 状态 | 备注 |
|---|---|---|
| 2D 空间 | ✅ SpatialGrid 200×200、A* 寻路、避障 | |
| HearingSystem | ✅ 距离分级听觉 | 比 Stanford 的单一 visual range 更细 |
| 情绪状态 | ✅ 由 Agent/Persona 与现行对话上下文承载 | 旧 `EmotionSystem` 从未接线，P-0824-H 已作为死代码删除 |

| Arbiter | ✅ LLM 每轮动态决策轨道 | |
| 并发 | ✅ Java 21 Virtual Threads | 优于 Stanford 串行 Python |

### 关键缺陷（已逐行核实）
1. **GroupStrategy listener 拿完整聊天记录**（buildContext 中 others 全量进上下文）→ 旁观者 100% 泄露密谈细节
2. **2D 对话完全无 Track**：ConversationManager 只用 ModeClassifier 硬规则（人数/情绪/立场）分 DYAD/GROUP/DEBATE，无信息隔离
3. **无偷听摘要管线**：HearingSystem 只输出"听没听到"，没有"听到什么→摘要→写记忆"
4. **无中断系统**：Agent 生成中世界变化无法终止 LLM 输出
5. **无社交性移动**：没有 MovementConstraint / 群体跟随 / 保持距离 / 回避
6. **MemoryStore 无检索打分**：只有窗口+压缩，没有 recency/relevance/importance 检索

## 三、外部调研结论（researcher，来源 arXiv/官方）

### 标杆方案
| 方案 | 空间感知 | 信息隔离 | 记忆 | 成本 |
|---|---|---|---|---|
| **Stanford Generative Agents** | 2D 小镇+visual range | ❌ 无显式隔离 | 🏆 memory stream+反思+计划 | 💸 25 agents×2天 ≈ 数千美元 |
| **Concordia (DeepMind)** | GM 语言介导 | 按场景由 GM 发放 | 联想记忆检索 | 高 |
| **OASIS** | 社交平台非物理 | 按关注关系 | 时间线 | 百万级靠抽样 |
| **AgentSociety (清华)** | 真实城市数据 | 按社会角色 | 环境状态库 | 10k agents 需分布式 |
| **狼人杀 LLM (清华 2309.04658)** | 无物理空间 | ✅ 逐 agent 私有上下文 | 反射摘要+经验池 | 中（压缩策略） |
| **我们的架构** | ✅ 200×200+A*+分级听觉 | ✅ Track 三模式（差异化） | ⚠️ 有存储无检索 | 未量化 |

### 关键证据（论文直接背书）
1. **"偷听只进摘要不进上下文"有原文支撑**：Stanford 论文 observation (3) *"Isabella Rodriguez and Maria Lopez are conversing about planning a Valentine's day party"* —— 旁听对话浓缩为一句观察存 memory stream，全文永不直接进上下文（arXiv:2304.03442 §3.2/§5）
2. **Track 隔离原理成立**：DACS 证明上下文污染是实证问题（跨 agent 污染 28-57%，隔离后 0-14%；arXiv:2604.07911）；狼人杀"身份只在自家 prompt"是 ISOLATED 的论文级先例
3. **Arbiter 是最大泄露风险**：若 Arbiter 每轮看到所有轨道全文，它本身就是旁路泄露源 → Arbiter 输入必须脱敏/摘要化
4. **最大风险是成本**（Stanford 数千美元/2天），不是架构可行性

### 独立判断（researcher）
> 方向正确（高置信）：三层融合 = Generative Agents 闭环的工程化升级，文献中不存在"空间+显式隔离+记忆"三合一现成方案，是有依据的创新组合。建议分阶段落地，从第一天带预算模型。

## 四、Demo 实证（coder，真实 LLM，2026-07-31 12:54）

### 实验设计
场景：A(侦探)+B(助手)密谈「仓库尸体、死者王大明、怀疑李四」；C(路人)在附近
方案一（现状）：C 拿完整对话记录 ｜ 方案二（Track WEAK）：C 只拿摘要 observation
每方案 2 轮真实 DeepSeek 调用，token 用 API usage 真值

### 量化结果
| 指标 | 方案一（现状） | 方案二（Track WEAK） | 结论 |
|---|---|---|---|
| **信息泄露率** | 🔴 100%（2/2 轮） | 🟢 0%（2/2 轮） | 隔离显著有效 |
| C 的 prompt token | 218 | 187 | ↓14% |
| 每轮 C 总 token | 320 | 284 | ↓11% |

### 实锤对话
- 方案一 C：「死者叫王大明，还提到李四可能跟这事有关」
- 方案二 C：「死者是谁……这我真不知道，我就是个路过的」

### 副作用（诚实记录）
- C 可能"太无知"（"路过打酱油的"略出戏）→ 3 条缓解：①摘要保留模糊观察（"发现了重要线索"而非纯情绪）②给旁观者推理空间 ③距离分级 WEAK（近，详细摘要）/ ISOLATED（远，完全隔离）

## 五、最终判断（综合三路证据）

### 结论：需求文档方案**可行且值得做**，但需按顺序落地

**理由（可量化证据）**：
1. 现状缺陷被 demo 实证：旁观者 100% 泄露 → 真实感无从谈起
2. 修复方案有论文背书：偷听摘要、Track 隔离都是验证过的模式
3. 成本不升反降：同场景 token ↓14%，且摘要固定长度不随对话轮数增长

### 落地路线（Phase 1-4，风险最低）
```
Phase 1（最小闭环，建议本周）:
  SpatialTrackResolver + TrackAssignment + InteractionDetector
  + 偷听摘要管线（HearingSystem → 摘要 observation → MemoryStore）
  + GroupStrategy listener 改用 WEAK 摘要（不拿全文）
  + Arbiter 输入脱敏
  → 交付：成本基线 + 泄露率基线（A/B 对照）

Phase 2:
  TrackStrategy 统一替换 Group/Debate/Dyad（保留旧类做兼容）
  + ContextVisibility 上下文过滤

Phase 3:
  World Director + Track Director 双导演（Arbiter 拆职责）

Phase 4:
  MovementConstraint / GroupAnchor 群体移动 + 中断系统 + 量化评估协议
```

### 中断系统（需求文档第十条）独立判断
- **必要且应作为底层能力**：2D 实时世界不能等 LLM 回合制
- 落地优先级：AgentTaskManager（Task ID 生命周期）→ CancellationToken（流式停止）→ WorldEventBus（事件驱动）
- 与 Track 联动：TRACK_CHANGED 事件 → 取消不属于新轨道的生成任务

### 风险清单（必须处理）
1. **成本叠加**：Arbiter + 每 agent + 摘要 = 每轮 3 类调用 → 预算模型 + 缓存 + 压缩
2. **Arbiter 泄露旁路**：Arbiter 输入必须摘要化
3. **摘要失真**：保留"说话者+主题+情绪基调"三要素，抽样校验
4. **人格漂移**：persona 锚定（身份锁定指令已加）+ 检索调参
5. **并发竞态**：SpatialGrid 共享状态 → 细粒度锁/copy-on-write
