## 一、结论（一句话根因）

> **P-0810-17（2026-08-10 批次）把 `POST /api/script/init` 默认改为「只生成概略 outline」（`outline_only` 缺省 true），完整剧本需由新增端点 `POST /api/script/generate_full` 异步补齐；但前端「生成剧本」链路从未接线 `generate_full`（前端 src 与 static bundle 零引用）——真实玩家路径下对局永远停在 `SETUP` 概略态，完整剧本（roles/秘密/线索/真相/killer_id）从不生成，`toMap.roles=[]`、`your_role=""`，前端显示「未分配角色」。用户看到的「角色完全没有逻辑」= 角色根本没被生成/分配，只有概略里的一句话人设。**

次级根因（基线 95b127b 即存在，非本次批次引入）：prompt 只传主题+角色数、角色名全靠 LLM 自由发挥且示例诱导占位名；LLM 失败/角色数不足时兜底/补位角色为「嫌疑人_X」占位名。

## 三、根因定位（证据代码片段）

### 根因 1（主根因）：init 默认 outlineOnly=true + 前端零接线 generate_full

**A. 后端默认只出概略** — `controller/ScriptController.java` L85-90：
```java
String mode = (String) body.getOrDefault("mode", "full");
// P-0810-17（阶段 1，两阶段生成）：outline_only 缺省 true —— init 只生成概略（快 <10s，
// 不再同步双 LLM 生成完整剧本+地图）；完整剧本+地图由 POST /api/script/generate_full 后台异步补齐。
boolean outlineOnly = body.get("outline_only") == null
        || Boolean.parseBoolean(String.valueOf(body.get("outline_only")));   // ← 缺省 true
```

**B. outlineOnly 分支不生成任何角色** — `service/ScriptGameService.java` L612-619：
```java
if (outlineOnly) {
    // 只生成概略（轻量 LLM 调用，快 <10s）：locations / roles（名字+一句话人设）/
    // clues（标题+地点）/ storyline / killer_hint —— 完整剧本+地图由 generate_full 异步补齐。
    Map<String, Object> outline = scriptService.generateOutline(theme, playerNames);
    game.outline = outline;
    game.name = outlineName(outline, theme);
    game.background = outlineStoryline(outline);
    game.phase = Phase.SETUP;   // 中间态：概略已生成、完整剧本待生成
    ...
    return game.toMap(...);   // ← 此路径从不调 applyScript，roles/assignments/secrets 全空
```
`ScriptGame.toMap`（L357+）SETUP 态输出：`roles=[]`、`your_role=assignments.getOrDefault(playerName,"")=""`、`your_secret=""`。

**C. 完整剧本生成函数仅 REST 可达** — `service/ScriptGameService.java` L774 + `controller/ScriptController.java` L134-139：
```java
public Map<String, Object> generateFull(String sessionId) { ... }   // 无任何自动调用方
@PostMapping("/generate_full")
public ResponseEntity<Map<String, Object>> generateFull(@RequestBody Map<String, String> body) { ... }
```

**D. 前端只有 init、没有 generate_full** — `roleplay-v4/frontend/src/components/ScenePage/ScenePage.tsx` L512-520：
```tsx
const genScript = async (mode: 'full' | 'chat' = 'full') => {
  ...
  const game = await api.scriptInit(scriptPrompt.trim(), players, mode, roomCode || undefined);
  // ← 之后直接 setScriptGame / setScriptMyRole / setScriptMySecret，无 generate_full、无 script_ready 监听
```
前端全量 grep：`generate_full|generateFull|script_ready|outline_only` 在 `roleplay-v4/frontend/src` 下 **0 命中**。

> 注意：P-0810-17 的测试（ScriptOutlineFullTest）通过 `outline_only=false` 显式走完整路径，测试本身不暴露该断链；断链只出现在「前端真实调用」这一条默认路径上。

### 根因 2（次级，基线即存在）：prompt 与角色卡零关联 + 占位名诱导

`service/ScriptSchemaV1.java` L46-72 buildPrompt：**只传 theme 与 playerCount，不传任何角色名/角色卡/玩家名单**：
```java
public static String buildPrompt(String theme, int playerCount) {
    return String.format("""
        你是一个剧本杀创作者。请根据以下信息生成一个完整的谋杀之谜剧本（剧本数据模型 Schema v1）。
        主题：%s
        角色数：%d
        ...
        "roles": [{"id": "role_1", "name": "角色1", "intro": "角色介绍", ...}],   // ← L72 示例直接是占位名「角色1」
```
- 前端剧本选择页精心选择的角色卡（侦探/管家/……）**完全不进入 prompt**，仅作为「玩家名单」决定角色数与兜底命名；
- prompt JSON 示例 `"name": "角色1"` 诱导 LLM 照抄输出「角色1/角色2」式占位名（与用户反馈的「嫌疑人_X」同属占位观感）；
- 角色分配 `Collections.shuffle`（ScriptGameService applyScript L718-726）随机打乱，玩家↔角色无任何逻辑映射（剧本杀抽卡可接受，但与「所选角色卡进剧本」的预期脱钩）。

### 根因 3（次级，基线即存在）：兜底/补位角色为「嫌疑人_X」

`service/ScriptSchemaV1.java`：
- L221-239 `defaultScript`：LLM 失败/空输出 → 角色 `"嫌疑人_" + 玩家名`（truth 也写成「凶手是<玩家0>」）；
- L433-472 `parseRoles`：LLM roles 缺失 → 按玩家兜底 `"嫌疑人_" + p`；
- `service/ScriptGameService.java` L725-726 applyScript 补位：
```java
// Leftover players get generic roles
for (int i = shuffledRoles.size(); i < game.players.size(); i++) {
    game.assignments.put(game.players.get(i), "嫌疑人_" + (i - shuffledRoles.size() + 1));
}
```
触发条件：LLM 输出角色数 < 玩家数（或 normalize 丢弃空名角色后数量不足）→ 剩余玩家拿「嫌疑人_N」。D-023 已修 maxTokens 600→4000 消除截断兜底，但 **LLM 失败/无 key/输出角色数不足** 时仍会命中本条。

## 四、修复建议清单（改动面最小 → 稳健，候选）

### 候选 A（前端接线，最小改动，恢复 P-0810-17 设计意图）
- ScenePage `genScript` 拿到 init 响应后（phase==='setup' 时）自动 `POST /api/script/generate_full`（带 session_id），并在 ChatPage/ScriptStatePanel 监听 `script_ready`/轮询 status 刷新完整对局状态；`chatMapEnabled` 等下游逻辑顺延到完整剧本就绪后。
- 改动面：前端 1-2 文件（client.ts +1 API、ScenePage/ChatPage 接线）。保留两阶段「快开」收益。
- 风险：需处理生成中 loading（toMap.generating 已暴露）与失败重试。

### 候选 B（后端 1 行回退，零前端改动，最快止血）
- `ScriptController.init`：`outline_only` 缺省改回 false（`body.get("outline_only")==null → false`），恢复基线同步完整生成路径；generate_full 保留供两阶段调用方显式使用。
- 改动面：后端 1 行 + yml 无。逐字节恢复 95b127b 行为（前端不动即好）。
- 代价：放弃两阶段快开（init 恢复 30-60s 完整剧本等待），与 P-0810-17 的提速目标相悖。

### 候选 C（后端自愈，推荐）
- initGame outlineOnly 分支生成概略后**自动异步触发 generateFull**（复用 discussionExecutor/generating 标记 + 幂等守卫：SETUP 且 generating=false 才触发；失败可重试），前端零改动、两阶段收益保留、对局必然到达完整剧本。
- 改动面：ScriptGameService.initGame outlineOnly 分支 +3-5 行（submit 异步任务），ScriptController 零改动。
- 可与 A 组合（后端自愈为主，前端 script_ready 监听为体验增强）。

### 候选 D（次级根因治理，角色与主题/所选角色真正挂钩）
- `buildPrompt` 增加角色名/角色卡输入：前端把所选角色卡名单传入 init（新增可选字段，如 `role_cards`），prompt 要求 LLM 按给定角色卡生成 roles（名字/人设沿用角色卡，补 secret/动机）；示例 JSON 把 `"角色1"` 改成具体化示例名（如「管家」「侦探」）防占位名诱导。
- `parseRoles`/`applyScript`：角色数 < 玩家数时用 players 名单补齐（而非「嫌疑人_N」）；`defaultScript` 兜底命名改用主题相关模板或直接复用玩家名（去掉「嫌疑人_」前缀观感）。
- 改动面：后端 ScriptSchemaV1 + ScriptGameService + ScriptController + 前端 ScenePage/client.ts，需配套测试。属功能增强，建议在 A/B/C 止血后单独批次做。
