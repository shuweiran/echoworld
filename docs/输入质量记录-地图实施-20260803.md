## 结论

1. **直接证据面干净**：9 个源码/测试/契约文件（#9-11、14-18、20-25）有效占比 ≈85-90%，无占位符/无假数据/无编造——实施结论 100% 来自源码定点读取与实测。
2. **噪声主源 = 门禁必读与过程输出**：三处合计约 88,900（占全部噪声 67%）——①并行作业登记历史 33,600（门禁必读但 83% 与实施无关）；②mvn 全量 INFO 日志 30,000（输出 86% 是逐行运行日志，有效信息只有尾部汇总）；③台账格式学习 25,500（历史批次描述）。三者都非选题本身，是**流程性开销**。
3. **无效输入 3 处 ≈600 字符（0.2%）**：edit 首次失败（<p> 不匹配）+ grep 空结果 + 输出过滤管道问题——均为探路性调用，失败即修正，未污染结论。
4. **冗余 0**：全部文件仅摄入一次；mvn 相关类跑了 2 次属验证必需（首次定位失败，二次确认修复），非重复摄入。
5. **回答主人问题**：做具体项目时，真正「干活」的输入（源码/测试/契约）几乎无垃圾；**无关输入主要来自三处流程开销——门禁必读的大历史文档（并行登记/修改记录）、构建工具的海量 INFO 日志、以及文档里与当前任务无关的历史功能条目**。若优化（日志降噪 -DtrimStackTrace/只看 surefire 汇总、台账按需 grep 单行、门禁文档瘦身），非有效占比可从 ≈45% 降至 ≈15%。
