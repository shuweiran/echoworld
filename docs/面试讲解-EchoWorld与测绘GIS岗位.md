# EchoWorld 面试讲解：测绘 / GIS / AI 复合岗位

适用岗位：测绘工程、遥感科学与技术、地理信息系统、摄影测量与遥感，以及具备软件工程、人工智能或大数据背景的复合型岗位。

## 60 秒项目介绍

> EchoWorld 是我用 Java 21 和 Spring Boot 开发的二维空间多 Agent 仿真引擎。多个 Agent 在共享地图里移动，后端根据坐标、距离、听觉范围和墙体遮挡判断它们能否交互，并通过 MERGED、WEAK、ISOLATED 三种上下文状态控制每个 Agent 能知道什么。React 和 Phaser 负责地图可视化，REST/SSE 负责实时状态同步；LLM 只生成语言和高层意图，碰撞、寻路、权限、地图校验和信息边界都由确定性规则约束。狼人杀和剧本杀只是验证隐藏信息隔离的场景。

## 必须诚实说明的边界

> EchoWorld 当前不是水利 GIS 或遥感处理软件。它没有 CRS 转换、GeoJSON/Shapefile 导入、遥感影像分类、DEM 分析或水文水动力模型。它能证明的是我具备空间数据建模、实时系统和 AI 工程基础，并知道下一步怎样把仿真核心接到专业 GIS 数据与业务模型上。

这句话很重要。它把“相关能力可迁移”和“已经做过专业业务”清楚分开。

## 面向水利勘测设计院的可迁移方向

如果把 EchoWorld 的技术用于水利/测绘场景，可按以下边界扩展：

1. **空间数据适配层**：GeoJSON、GeoTIFF、矢量/栅格图层、EPSG 坐标系；
2. **专业空间对象**：河道、闸门、泵站、堤防、监测点、风险区；
3. **动态事件**：水位、流量、设备告警、人员巡检和应急调度；
4. **规则与 AI 分工**：水文计算和安全阈值使用确定性模型，LLM 只做报告解释、信息检索和辅助交互；
5. **成果表达**：WebGIS 地图、时序图、空间告警和方案对比，而不是游戏化角色界面。

## 三个核心技术故事

### 1. 空间如何形成认知边界

从坐标与听觉出发，经 `HearingSystem` 和 `SpatialTrackResolver` 得到三态 Track。重点解释为什么需要 `WEAK`：空间旁听不是全知，也不是完全无知。

### 2. 如何防止秘密泄漏

`TrackStrategy` 为每个 Agent 单独构造上下文。`MERGED` 获得全文，`WEAK` 只获摘要，`ISOLATED` 完全没有组对话；测试直接断言秘密短语不进入旁听者和隔离者 prompt。

### 3. 如何约束 LLM

LLM 不拥有坐标、碰撞、权限和状态机写权限。SpeechGate 在调用模型前决定是否值得发言；测试用 mock/fake LLM，核心 CI 不依赖真实 Provider。

## 高频追问与回答要点

### 为什么使用 Spring Boot？

需要 REST/SSE、配置绑定、依赖注入、数据库和测试上下文；同时 Java 对确定性状态机、并发和长期维护更合适。

### 为什么使用 SSE，而不是 WebSocket？

当前主要需求是服务端持续推送世界状态和 Agent 输出，客户端控制仍走 REST。SSE 连接模型简单、浏览器原生支持、自动重连方便；如果未来需要高频双向位置同步，再评估 WebSocket。

### 为什么是三态 Track？

二态无法表达旁听。`WEAK` 允许 Agent 知道“发生了交谈”，但拿不到秘密原文，空间接近时认知能渐进变化。

### 最大技术债是什么？

`ConversationManager`、`SimulationService` 和 `SimulationController` 职责偏大；前端仍保留历史原型目录名；缺少公开固定 Demo、SpeechGate benchmark 和专业 GIS 数据适配。

### 系统能支持多少 Agent？

当前定位是小到中等规模，不能在没有 benchmark 时给出夸张数字。已有空间网格、轻量群演和有界异步队列，但仍需固定硬件和工作负载下做容量测试。

### AI 帮你做了什么？

> 我使用 Codex 做代码生成、测试补齐和重复性重构；系统目标、Track 模型、信息隔离边界、模块约束和验收条件由我定义，并通过自动化测试和真实场景复核生成结果。

这段话只在你逐条理解核心实现后使用。
